## 三、ES Module 迁移三要点（关键！）

1. **顶层函数/变量不自动挂 window**（普通 script 会，module 不会）。
   → 所有被 `onclick`（静态 HTML + 动态 innerHTML 字符串）引用的函数，以及被测试 `window.openXxx()` 调用的游戏函数，**必须在入口显式挂载**。
   → 挂载分两种（见 app.js 末尾）：
     - **函数 & 常量**：`Object.assign(window, {...})` 值挂载（含 `function` + `async function`）
     - **可变状态（let/var）**：`Object.defineProperty(window, name, { get: () => name })` getter 挂载
       —— 避免挂在 init() 完成前的初始值（stale 问题），`window.content`/`gameState` 等始终反映模块变量最新值
2. **外部全局需加 `window.` 前缀**：`zzfxR` 等在普通 script（先于 module 执行）定义，module 里裸引用会 ReferenceError。已改 `zzfxR`→`window.zzfxR`。`window.MUSIC_SONGS` 原本就带前缀，无需改。
3. **module 是 defer 语义**：在 DOM 解析完后执行。普通 script（zzfx 库/music.js）同步先执行 → 顺序正确。DOM 依赖更安全。

## 四、统一游戏生命周期（根治资源泄漏）

每款游戏遵循 `open(cfg, onComplete)` 约定：

```js
export function openPacman(cfg, onComplete) {
  // 1) 创建 overlay 并 append
  // 2) 注册监听：document.addEventListener / canvas.addEventListener
  // 3) 起 rAF / setInterval
  // ... 玩法 ...
  function closeGame() {
    // 4) 必须对称清理：removeEventListener × 所有 + cancelAnimationFrame + clearInterval
  }
}
```

**硬性规范**：
- 进游戏注册的 `document`/`canvas` 监听，关闭时全部 `removeEventListener`
- `rAF`/`setInterval` 关闭时 `cancel`/`clear`
- 结果弹窗（ty-result）关闭后同样清理
- 验收：连开/连关同一游戏 5 次，无 rAF 累积、无重复监听（smoke 每游戏后强制刷新隔离已覆盖）
