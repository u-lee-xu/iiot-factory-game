章节导言 ​

前四章，你从网络基础一路走到了边缘计算。现在设备已经连网（第 3 章）、数据已经在边缘做了第一轮筛选（第 4 章），接下来数据要去哪里？

答案是工业互联网平台。如果要把前面学过的所有东西串成一条完整的链路——设备通过现场总线连到网关（第 3 章），网关在边缘侧做数据预处理（第 4 章），处理后的数据向上发送——那么"向上"的目的地就是平台。平台负责把海量设备的数据存下来、分析好，并在上面运行各种各样的工业应用。

这一章要回答的是：工业互联网平台到底是什么？它像一家快递公司的中央调度系统吗？中国的平台版图长什么样？以及什么技术能让工业应用在平台上像快递包裹一样被快速部署和迁移——Docker 容器。

环境确认：本章实践在 Ubuntu 虚拟机上安装 Docker，部署 Node-RED 容器。请确认虚拟机可访问互联网（拉取镜像）、SSH 连通。

5.1 快递调度系统与工业平台的共同逻辑 ​

想象一家大型快递公司的中央调度系统。每天成千上万个包裹从全国各地发出，调度中心协调着全网的车队、分拣中心和派送员——哪辆车走哪条路线、哪个仓库优先处理哪批货物、哪位派送员负责哪个片区，全部由系统统一调配。

在这个过程中，有一层"平台"替你处理了所有复杂协调。发货人不需要知道包裹具体由哪辆卡车运送、经过哪个中转站；派送员也不需要了解全网的路况和其他人的工作安排。因为调度系统在两者之间屏蔽了所有底层差异——发货人只管交件，派送员只管按系统指令配送。

工业互联网平台遵循完全相同的逻辑，只是服务的对象从快递包裹变成了工厂里的设备、数据和工业应用。

工信部/AII 定义：《工业互联网平台白皮书》（2019）：面向制造业数字化、网络化、智能化需求，构建基于海量数据采集、汇聚、分析的服务体系，支撑制造资源泛在连接、弹性供给、高效配置的工业云平台。

通俗版：向下连接并管理海量工业设备，向上承载并支撑各类工业应用，中间层提供数据存储、分析和开发工具。

5.2 边缘与平台分工：管"现在" vs 管"趋势" ​

承接第 4 章：边缘计算已在现场做了预处理、本地决策、筛选上传。平台层接手后做什么？

维度边缘侧 (第 4 章)平台侧 (本章)
时间范围当下、秒级、分钟级小时、天、月、年、全生命周期
数据量原始高频 → 筛选后低频全量历史、聚合后、多源融合
计算任务阈值判断、滑动均值、简单规则、协议转换趋势预测、相关性分析、AI 训练/推理、跨产线优化
典型问题"当前温度是否超标？""过去半年振动趋势是否恶化？未来 72 小时故障概率？"
响应时延< 10ms (本地闭环)秒~分钟级 (云端分析)
离线能力完全自治、本地缓存依赖网络、边缘补传后分析

一句话记住：边缘管"现在"(实时判断)，平台管"趋势"(历史分析)。两者协同，才构成完整的工业互联网数据处理链路。

真实案例：树根互联 + 三一重工（第 2 章回顾 + 本章深化）[3] ​

  • 设备接入：每台挖掘机/泵车装传感器+通信模块 → 4G/5G → 根云平台设备接入层（协议解析、设备模型）
  • 数据/分析：时序数据库存全量运行数据 → 流计算实时算油耗/工时/故障码 → 批计算训练液压泵 RUL 模型 → 模型下发边缘网关
  • 应用托管：设备管理看板、远程监控 APP、维修工单系统、挖掘机指数大屏 → 运行在平台应用层，面向租赁商/车主/三一总部

三层能力闭环：接入(向下) → 分析(中间) → 应用(向上) → 反馈指令下发边缘/设备。

5.4 Docker 容器：让工业应用像手机 APP 一样部署 [4] ​

5.4.1 集装箱的启示 ​

远洋运输业 1950 年代的革命——集装箱：无论电视机还是水果，装进标准铁箱，码头用同一套吊机装卸、同一套卡车转运。船不在乎箱子里装什么，港口也不在乎。

Docker 对软件做的事，和集装箱对货物做的事完全一样。

一个 Docker 镜像把应用程序 + 它需要的全部依赖（OS 库、运行时、配置文件）打包成一个标准化"箱子"。这个镜像可以在任何安装了 Docker 的机器上运行——你的 Ubuntu 虚拟机、阿里云服务器、车间机柜里的工控机——运行结果完全一致。部署不再需要"装依赖、配环境、调兼容性"三步走，一条命令就够了。

5.4.2 镜像 vs 容器 vs 仓库（核心三概念） ​

概念类比集装箱说明
镜像标准化的空集装箱(设计图纸)只读模板，分层存储，包含应用+依赖+配置
容器装好货、正在运输的集装箱镜像的运行实例，可读写层，隔离进程空间
仓库集装箱堆场/调度中心存储/分发镜像的地方（Docker Hub、Harbor、阿里云镜像仓库）
docker pull nginx     # 从仓库拉取镜像到本地
docker run -d nginx   # 基于镜像启动一个容器(运行实例)

5.4.3 容器 vs 虚拟机：本质区别（必考）[5] ​

维度虚拟机 (VMware/VirtualBox)Docker 容器
类比独立别墅：每栋自带水电系统标准化集装箱：共享货轮发动机和电力
隔离级别硬件级（Hypervisor 模拟 CPU/内存/网卡）进程级（Linux Namespace + Cgroups）
启动速度分钟级(启动整个 OS)秒级(只启动应用进程)
磁盘占用每个 VM 几 GB每个容器几十~几百 MB
性能损耗5-10%(硬件虚拟化开销)近原生(无虚拟化开销)
适用场景需不同 OS 内核、强隔离、遗留应用同一 Linux 下快速部署大量应用

工业边缘网关为何选容器？ 网关算力弱（ARM 4 核、4GB 内存），跑 1 个 VM 就满了；跑 10 个容器轻松。且镜像保证 10 台网关环境完全一致——云端构建镜像 → 10 台网关同一条 docker run → 零差异部署。

本章小结 ​

本章我们从快递调度系统类比出发，理解了工业互联网平台作为"中间层"的三层核心能力（设备接入/数据分析/应用托管），通过三一重工+树根互联案例看到了三层能力闭环，也理清了中国平台版图的双基因逻辑（互联网向下输出 vs 制造业向上沉淀）与"双跨"平台含义。

在实践中，我们第一次接触 Docker 容器——从"集装箱"类比理解其核心价值：将应用与依赖打包成标准化镜像，实现"一次构建，到处运行"。我们在 Docker 中运行了 Nginx 与 Node-RED，通过双开对比直观感受了容器化部署相对于传统安装的优势——秒级启停、环境隔离、删除即净化、数据卷持久化。

衔接提示：第 6 章我们将在 Node-RED（原生或容器均可）基础上，加装 Dashboard 节点，开发工业 APP 看板——把边缘采集、平台存储的数据，变成操作工、班长、厂长一眼能看懂的可视化界面。

选择题 ​

  1. 以下哪项不是工业互联网平台的核心能力？ A. 设备连接与管理　B. 数据存储与分析　C. 直接代替 PLC 执行控制逻辑　D. 应用开发与托管

  2. 树根互联平台是由哪家企业孵化的？ A. 阿里巴巴　B. 华为　C. 海尔　D. 三一重工

  3. 海尔卡奥斯平台的核心模式是？ A. 工程机械远程监控　B. 大规模定制　C. 5G 专网部署　D. 芯片设计

  4. Docker 镜像和容器的关系是？ A. 容器是镜像的只读模板 B. 镜像是容器的运行实例 C. 镜像是只读模板，容器是从镜像运行出来的实例 D. 两者完全相同，只是叫法不同

  5. Docker 与虚拟机相比，以下哪项是 Docker 的优势？ A. 完全硬件级隔离　B. 可以运行不同操作系统的应用　C. 启动速度快、资源占用小　D. 不需要宿主机操作系统

判断题 ​

  1. （ ）工业互联网平台的"设备接入层"负责协议解析、设备注册、证书管理。
  2. （ ）"双跨"平台是指跨行业、跨领域的工业互联网平台，代表最高水平。
  3. （ ）Docker 容器之间完全隔离，不能共享宿主机内核。
  4. （ ）docker run -v /host/path:/container/path 可以实现容器数据持久化。
  5. （ ）Node-RED 运行在 Docker 容器中时，删除容器默认会保留 Flow 数据。
  6. （ ）边缘网关上运行的 Node-RED 容器，镜像由云端统一构建下发，体现"云端管控、边缘执行"。

习题答案 ​

选择题答案：1-C　2-D　3-B　4-C　5-C

简要解析：① 平台连接设备/存数据/托管应用，但不代替 PLC 执行实时控制；② 树根互联由三一重工孵化；③ 卡奥斯核心模式=大规模定制（C2M）；④ 镜像是只读模板，容器是镜像的运行实例；⑤ Docker 启动快、资源占用小（进程级隔离）。

判断题答案： 1.（√）设备接入层负责协议解析、设备注册、证书管理、拓扑建模。 2.（√）"双跨"=跨行业、跨领域，代表我国工业互联网平台最高水平。 3.（×）Docker 容器共享宿主机内核（进程级隔离），不是完全独立。 4.（√）-v 宿主路径:容器路径 实现数据卷持久化。 5.（×）容器内数据默认在可写层，删除容器即丢失；要保留须挂载数据卷（-v）。 6.（√）云端统一构建镜像 → 下发到各边缘网关运行，体现"云端管控、边缘执行"。

思考题参考要点：

  1. 自建机房监控系统：不算用了"工业互联网平台"——平台的核心是"海量设备接入 + 数据汇聚分析 + 应用生态"的开放中间层，自建封闭系统缺平台化能力。
  2. 中小注塑机厂远程运维：选"使用工业互联网平台"（如树根互联类）性价比最高——3 个软件工程师自建平台成本高、周期长；用平台可快速实现设备上云、远程诊断，按需付费。
  3. 镜像=只读模板（"应用安装包"），容器=镜像的运行实例（"已安装的应用"）；一个镜像可启动多个容器。
  4. 虚拟机=整机虚拟化（Hypervisor+客户机 OS，分钟级启动、几 GB 磁盘）；Docker=进程级隔离（共享内核，秒级启动、几十 MB）。边缘网关算力弱，跑 1 个 VM 就满、跑 10 个容器轻松，且镜像保证多台网关环境一致——所以工业边缘部署用容器。
