章节导言 ​

前五章我们走完了工业互联网的"底层"和"中层"——设备怎么连（第 3 章）、数据在边缘怎么处理（第 4 章）、数据上传到平台后怎么管理（第 5 章）。现在只剩下最后一件事：把这些数据变成人看得见、用得上的东西。

这就是工业 APP要做的事情。

承上启下：还记得第 2 章的 IIRA 四层模型吗？第 4 章学过的"边缘层"负责设备数据采集，第 5 章学过的"平台层"负责数据存储和分析，而本章的"工业 APP"就是 IIRA 最上面的应用层——直接面向操作工人和管理者的软件界面。

一台设备在工厂里运行，它的振动、温度、压力数据每秒都在产生。但数据本身不会说话——把它们变成仪表盘上的指针、趋势图上的曲线、手机上的报警通知，变成维修班长和车间主任能一眼看懂的信息，才是工业互联网的"最后一公里"。这一章，我们将用已经熟悉的 Node-RED，给它加上"界面"能力，亲手开发一个完整的产线设备监控看板。

环境确认：本章在 Node-RED（原生 1880 端口或 Docker 1881/1882 端口）中安装 Dashboard 插件。请确认 Node-RED 可访问、Modbus 节点已安装。

6.1 两种 APP，同一个逻辑 ​

用户每天都会用到快递查询 APP——打开顺丰或中通的 APP，输入单号就能看到包裹到哪了。用户不需要知道包裹是怎么分拣的、货车走哪条高速、转运中心怎么调度，APP 把复杂的物流流程全部封装在后台，只呈现一个简洁的查询界面。

[图6-1 快递查询 APP 类比图]

类比理解：工业 APP 就像快递查询 APP。工厂操作工打开设备监控 APP，就能看到设备温度、振动和运行状态，但他不需要懂 Modbus 协议、不需要会编程、不需要知道数据是怎么从传感器传到平台的——复杂的工业流程被封装在后台，APP 只把最关键的信息送到他面前。

工业互联网平台上跑的"工业 APP"遵循完全相同的逻辑。不同厂商开发的设备监控 APP、质量分析 APP、能耗管理 APP——它们运行在同一个工业互联网平台上，共享平台的数据存储、分析引擎和设备管理能力。开发者面向平台的标准接口编程，用户从平台的应用市场下载使用。主流工业互联网平台（如树根互联、卡奥斯）都提供了应用市场，开发者将 APP 上传到市场，企业用户像装快递查询 APP 一样搜索、安装、使用。

6.2 低代码：用积木搭应用 ​

6.2.1 矛盾与答案 [5] ​

工业 APP 需要快速开发、快速迭代，但工厂里的设备工程师、工艺工程师不一定是程序员。怎么让"不会写代码的人"也能做工业 APP？

答案就是低代码。

传统软件开发：需求文档 → UI 设计 → 前端代码 → 后端接口 → 测试 → 运维部署——至少三种专业角色、数周时间。

低代码思路：把常见功能抽象成"积木块"——图表是一块、按钮是一块、仪表盘是一块、表格是一块。你不需要写 HTML/CSS/JavaScript——只需要把积木拖到工作区、连线、配置参数、点部署。

类比：低代码开发就像搭乐高积木建快递分拣台。不用从锯木头、拧螺丝造传送带，只需把现成积木块拼起来——传送带积木、分拣口积木、传感器积木——很快搭出能运转的模型。

[图6-3 低代码"搭积木"开发示意]

6.2.2 低代码的"低"在哪里？ ​

低在"从零写代码"的比例降低了：

  • 传统开发：100% 代码（从第一行 HTML 写起）
  • 低代码开发：80% 常见需求拖拽完成，20% 特殊逻辑手写代码

关键：低代码不排斥写代码，它只是让 80% 常见需求不用写代码。Node-RED 中的 Function 节点（写 JavaScript） 就是当你需要的逻辑无法用现有积木拼出来时的"后门"。

6.2.3 公民开发者 [4] ​

当业务人员而不是程序员开始使用这些工具搭建工业 APP 时，他们被称为**"公民开发者"**——Gartner 提出的概念，正在工业互联网领域快速普及。

Gartner 预测（2021）：到 2023 年，大型企业中活跃的公民开发者数量将达到专业开发者数量的 4 倍。

你已经是公民开发者了：第 3 章拖拽 Modbus Read 节点做协议通信，第 4 章拖拽 Switch 节点做阈值判断，第 5 章在 Docker 里跑 Node-RED——这些操作本质上都是在"搭积木"。

6.3 Node-RED Dashboard：给数据加上界面 [3] ​

本章要给 Node-RED 增加一类全新的积木——Dashboard 节点。它们负责把数据变成界面：

组件核心用途关键配置
Gauge仪表盘指针显示单值量程、单位、颜色分段(绿/黄/红)
Chart时间序列趋势线折线/柱状、X轴时长、多线(用 topic 区分)
Button用户点击触发动作文本、颜色、输出 payload
Text显示文本/数值模板 \{\{msg.payload\}\}、单位
Notification像手机通知栏弹出消息级别(info/warn/error)、时长
LED红/黄/绿指示灯值绑定颜色规则、位置显眼

布局系统（三级）：

  • Tab（标签页）：顶层，如"产线监控"、"历史分析"
  • Group（分组/卡片）：Tab 下的矩形区域，带标题，如"仪表盘区"、"趋势图区"
  • Widget（部件）：单个 Dashboard 节点，分配到 Group

6.6 工业 APP 安全：不能忽视的底线 ​

安全维度要求Node-RED Dashboard 落地
访问控制只有授权人员访问看板ui_control 节点设置登录页、用户名密码保护
数据加密传输加密（HTTPS）反向代理 Nginx + SSL 证书终止（生产必配）
权限管理不同角色不同权限Dashboard 原生不支持，需平台层网关/认证服务实现
日志审计记录谁在何时做了什么Node-RED 日志 + 平台审计日志双重保障

本章最低要求：在 Dashboard 中开启基础登录保护（ui_control），理解 HTTPS/权限/审计在生产环境由运维配置，但理解这些原则是工业 APP 开发必修课。

本章小结 ​

本章我们从快递查询 APP 类比出发，明确了工业 APP"小而精、快速迭代、领域工程师可开发、平台托管、订阅制"的五大特征，区分了设备监控/分析诊断/预测预警/操作辅助/管理决策五大类型，理解了低代码"80%拖拽+20%编码"的核心思想与"公民开发者"概念。

在实践中，我们安装了 Node-RED Dashboard，逐一掌握了 Gauge、Chart、Button、Text、Notification、LED 六大组件的配置要领，理解了 Tab→Group→Widget 三级布局体系，并复用第 4 章传感器模拟数据源，完整开发了一个产线设备监控看板——双仪表盘联动 LED、双线趋势图、文本读数、按钮交互、超温弹窗告警，功能完整、界面清晰。

衔接提示：第 7 章我们将学习工业数据采集与传输——把看板的数据源从"模拟函数"换成真实的 MQTT 协议采集，打通"设备→边缘网关→MQTT Broker→Node-RED→Dashboard"的完整工程链路。

  4. 从第 3 章的 Modbus 传感器模拟到今天 Dashboard 上的仪表盘指针摆动，数据经历了多少"站"？画出一张完整链路图，并标注每一站对应的章节。

习题答案 ​

选择题答案：1-C　2-C　3-B　4-D　5-C　6-B

简要解析：① 工业 APP 突出特征=小而精、快速迭代；② Dashboard 插件用于创建 UI 和数据可视化；③ Chart 多线用 msg.topic 区分；④ 布局顺序 Tab→Group→Widget；⑤ 特殊逻辑用 Function 节点写 JavaScript；⑥ Gauge 颜色分段帮操作员按数值区间快速判断状态。

判断题答案： 1.（×）工业 APP 的一大特点就是领域工程师/公民开发者也能做（低代码）。 2.（√）MES、ERP 是传统大型工业软件的典型代表。 3.（×）低代码是"80% 拖拽 + 20% 编码"，不排斥写代码。 4.（√）Notification 节点可像手机通知栏一样弹出提示。 5.（×）Gauge 可显示小数（值格式 \{\{msg.payload\}\}）。 6.（×）一个 Chart 节点可用 msg.topic 区分多条数据线。 7.（√）本章数据源可复用第 4 章电机传感器模拟节点。

思考题参考要点：

  1. MES 拆 APP 举例：设备实时监控 APP、工单进度跟踪 APP、质量追溯 APP、能耗分析 APP、排产可视化 APP——每个聚焦单场景、可独立迭代。
  2. 拖拽完成：布局（Tab/Group）、节点连线、配置参数（Gauge 量程/Chart 主题/Notification 级别）；必须写 JS：Function 里的数据转换、按 topic 拆分多线等"积木拼不出"的逻辑。低代码边界=常见功能积木化、特殊逻辑留"代码后门"。
  3. 改进点示例：历史趋势对比、异常声音/闪屏提醒、移动端适配、按角色权限显示、多产线汇总页。
  4. 完整链路：PLC/传感器（第 3 章 Modbus 采集）→ 边缘网关（第 4 章 Node-RED 预处理）→ 平台存储（第 5 章）→ MQTT 传输（第 7 章）→ Dashboard 看板（第 6 章）；本章先用第 4 章"电机传感器模拟"Function 当数据源（后续第 7 章换真实 MQTT）。
