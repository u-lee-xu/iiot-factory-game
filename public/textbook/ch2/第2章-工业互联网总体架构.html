章节导言 ​

第 1 章我们学习了互联网如何连接全世界的计算机和人。但如果把"连接对象"从手机和电脑换成工厂里的机床、机器人和传感器——会发生什么？

答案就是工业互联网。

它不是简单地把工厂设备插上网线。工业互联网要面对的是高温油污的车间、毫秒级的控制精度、断网就可能出事故的可靠性要求。这一章将带你走进工业互联网的世界：它从何而来、和普通互联网有什么本质区别、一套完整的工业互联网系统由哪些部分组成，以及这个产业中有哪些角色和正在发生的商业模式变化。你还会在动手环节掌握远程管理服务器的基本技能——SSH 登录和 Linux 命令，它们是你后续深入学习的关键工具。

环境确认：本章实践需通过 SSH 连接模块零搭建的 Ubuntu 虚拟机，并创建云服务器。请确认虚拟机桥接模式、SSH 连通正常。

学这一章的心态（写给零基础的你）：咱们才学第 2 周，别被"架构模型"四个字吓住。这一章的正确打开方式是——先用黑灯工厂 + 数据闭环搞懂"工业互联网到底在干什么"（建立感性认识），再把 IIRA/ISA-95 当成一张全书地图认个路（知道后面每章在哪个位置）。地图上的细节不用背，第 3~7 章用到哪一层，我们会回来细讲哪一层。

2.1 从"黑灯工厂"看工业互联网的本质 ​

2.1.1 走进真实的智能工厂 ​

2020 年 8 月，小米公司在北京亦庄投产了一座"智能工厂"[8]。这座工厂的年产能是 100 万台高端智能手机，但产线上的工人数量几乎为零——从电路板印刷、元器件贴装到整机组装和包装，全部由机械臂和自动化设备完成，产线可以在无人值守的情况下连续运行。据公开报道，该工厂的自动化率超过了 95%，生产线上的许多环节已经实现了"关灯作业"——也就是在完全没有照明的环境下由机器自主完成生产。

特斯拉上海超级工厂的焊装车间也采用了类似的模式[8]：超过 300 台工业机器人协作完成车身焊接，整个过程无人干预。这些"黑灯工厂"的背后，是成千上万传感器、控制器、执行器通过工业网络实时协同，数据上传平台实时分析、决策下发。

核心洞察：黑灯工厂不是"没人"，而是"人退出了重复性劳动，转向监控、优化、决策"——这正是工业互联网的价值：让数据替代经验，让算法辅助决策，让机器自主协同。

2.1.2 数据闭环：让黑灯工厂"活"起来的血液循环 ​

上一节（2.1.1）看到的黑灯工厂能"关着灯干活"，靠的不是机器"自己会思考"，而是一套让数据不停转圈的系统：传感器感知现场，网络把数据传上去，边缘/平台把数据分析成决策，执行器动手干活，干完的结果又被新一批传感器感知到——数据就这样一圈一圈地转，工厂才真正"活"了起来[11]。

贯穿全章的核心隐喻：所有工业互联网场景，本质都是"数据闭环"在不同环节的体现——它也是全书最底层的一张"总图纸"，第 8 章的全景图会再次回到它。

感知(传感器/PLC) → 传输(现场总线/工业以太网/5G/MQTT)
    → 分析(边缘计算/平台大数据/AI模型)
    → 决策(规则引擎/优化算法/专家经验)
    → 执行(PLC/执行器/AGV/工单派发)
    → 再感知(形成闭环)

2.1.4 工业互联网 vs 消费互联网：七大核心差异（必考） ​

维度消费互联网工业互联网本质原因
连接对象人、手机、PC机床、机器人、传感器、PLC服务对象不同
可靠性要求秒级容忍、重试即可毫秒级、零丢包、确定性关乎生产安全、设备寿命
工作环境办公室、家庭、商场高温、油污、振动、强电磁干扰物理环境恶劣
数据特征文本、图片、视频、日志高频时序、多模态、强实时物理过程数据
时延要求亚秒~秒级可接受毫秒~微秒级（运动控制）控制回路决定
生命周期App 迭代周周更设备 10-20 年、协议 20 年不变资产长周期
安全后果隐私泄露、账号被盗设备损毁、环境污染、人员伤亡物理世界安全

类比：消费互联网像"城际高铁"（载人、舒适、晚点可接受）；工业互联网像"工厂专用轨道车"（载货、精准、绝不脱轨）。

2.2 全书地图：IIRA 四层 + ISA-95 五层（先"会用"，再"用熟"） ​

这一节怎么学：前面我们搞懂了工业互联网"在干什么"（黑灯工厂 + 数据闭环）。接下来给它画一张全书地图——两套模型把整本书的知识点都钉在各自的位置上。 先别背：第 2 周只要求做到两件事——(1) 能看懂这张地图每一层是干什么的；(2) 知道后面哪一章会用哪一层。地图上的设备名、协议名、细节，第 3~7 章用到时都会回来细讲。所以这节"看得懂、会指路"即可，不要求背熟。

2.2.1 两句话读懂两套模型 ​

  • IIRA 四层（功能视角，问"做什么"）：国际工业互联网联盟 IIC 的参考架构，本教材取其功能分层的核心思想，简化为 边缘层 → 平台层 → 应用层 → 业务层。一句话：数据在车间边缘就近处理，在云端平台汇聚分析，以工业 APP 的形式被人使用，最终服务于企业经营管理。[3]
  • ISA-95 五层（部署视角，问"装哪里"）：国际自动化标准（ISA-95/IEC 62264），把工厂从设备到企业分为 L0 现场设备 → L1 控制 → L2 监控 → L3 运营 → L4 业务。一句话：从"最贴机器的层"到"最贴老板的层"共五层。[4]

2.3 工业互联网五大构成要素 ​

先分清两套说法：

  • 官方三大体系（2017 国务院《关于深化"互联网+先进制造业"发展工业互联网的指导意见》、AII《工业互联网体系架构 2.0》2019）[1]：网络、平台、安全——回答"工业互联网靠什么支撑"。
  • 本书五大构成要素（教学扩展）：在三大体系基础上补充应用与生态——回答"整个工业互联网产业由哪些部分组成"。

一句话区别：三大体系 = 地基（网络/平台/安全）；五大要素 = 地基 + 上面的产品（应用）+ 周围的产业（生态）。五大要素 ⊃ 三大体系，表中前三项即官方三大体系。

2.5 商业模式变革：从卖产品到卖服务 ​

2.5.1 劳斯莱斯"按小时卖推力" ​

航空公司不买发动机，按飞行小时付费；劳斯莱斯远程监控所有发动机健康状态，负责全维护。核心逻辑：工业互联网提供"远程看见"能力 → 厂商敢承诺可用性 → 利益绑定 → 双赢。[6]

2.5.2 空压机"卖压缩空气" ​

阿特拉斯·科普柯、凯撒免费装机，装流量计按用气量收费[9]。厂商远程监控能效，主动保养。同构模式：手机流量计费、AI 大模型 Token 计费。

2.5.3 三一重工"挖掘机指数" ​

数十万台挖掘机上传开工率 → 宏观经济先行指标 → 树根互联平台价值[5]。厂商主动派工程师换液压泵，客户买的是"设备可用时间"。

本质：制造即服务——设备不出厂就结束责任，而是通过数据闭环实现全生命周期服务变现。

本章小结 ​

本章我们从黑灯工厂出发，先建立了"数据闭环"这个最底层的感性认识（黑灯工厂为什么能黑灯——数据在"感知→传输→分析→决策→执行→再感知"里一圈圈地转），再梳理三大起源脉络（GE/工业4.0/中国制造2025）与七大核心差异，然后把 IIRA/ISA-95 当作全书地图认了路（细节留给第 3~7 章用到再讲），最后理解了五大构成要素、四类生态角色，以及从"卖产品"到"卖服务"的商业模式变革（劳斯莱斯/空压机/三一案例）。

在实践中，我们掌握了 SSH 远程登录、Linux 基础 9 大命令、apt 软件管理、云服务器创建与安全组配置——这些是后续所有远程开发、边缘部署、平台运维的通用生存技能。

衔接提示：第 3 章我们将深入车间现场，解决"西门子说 ProfiNet、三菱说 CC-Link、施耐德说 Modbus"的设备通信互联问题，对应 ISA-95 L0-L1 层，对应 IIRA 感知控制层与边缘层交界。

判断题 ​

  1. （ ）德国"工业4.0"和"工业互联网"虽然名称和切入点不同，但底层逻辑一致——让设备联网、让数据驱动决策。
  2. （ ）工业互联网平台层的典型功能包括数据存储、大数据分析和 AI 模型训练。
  3. （ ）安全层在工业互联网中是独立的一层，与其他四层并列。
  4. （ ）系统集成商的工作是把不同厂商的设备和平台对接起来，打通整个系统。
  5. （ ）红领集团（酷特智能）的大规模定制案例说明，数据闭环可以用于"管产品"而不仅仅是"管设备"。
  6. （ ）apt 是 Ubuntu 的软件包管理器，类似于手机上的"应用商店"。
  7. （ ）云服务器本质上就是别人机房里的一台虚拟机，你通过互联网按需使用。
  8. （ ）在 IIRA 架构中，应用层直接负责采集传感器的原始数据。

习题答案 ​

选择题答案：1-B　2-D　3-D　4-B　5-B　6-C　7-B

简要解析：① "Industrial Internet" 由 GE 于 2012 年提出；② 可靠性/环境/数据特征/延迟都是真实区别，而"连接对象是人"是错误说法，故 D 为"不是区别"；③ PLC/传感器属于边缘层（现场感知控制）；④ 闭环=数据从采集到执行再反馈的完整回路；⑤ Power by the Hour=按飞行小时收服务费；⑥ 挖掘机指数=三一重工（树根互联）；⑦ AII 三大体系=网络/平台/安全。

判断题答案： 1.（√）德国工业4.0 与工业互联网底层逻辑一致——让设备联网、数据驱动决策。 2.（√）平台层典型功能含数据存储、大数据分析、AI 模型训练、应用托管。 3.（×）安全是贯穿全系统的保障体系，不是与其他四层并列的一层。 4.（√）系统集成商的核心工作就是把不同厂商设备、平台、应用对接交付。 5.（√）红领集团（酷特智能）C2M 大规模定制证明数据闭环可"管产品"而非只"管设备"。 6.（√）apt 是 Ubuntu 软件包管理器，类似手机"应用商店"。 7.（√）云服务器本质上就是云端机房里的虚拟机，按需使用。 8.（×）采集传感器原始数据的是边缘层（感知控制），不是应用层；应用层是面向场景的 APP。

思考题参考要点：

  1. 不是工业互联网：连接对象是消费设备、可靠性秒级即可、环境民用、数据非高频时序、安全后果低——用七大差异逐项判断均为"消费互联网"特征。
  2. IIRA 四层各做什么：边缘层（网关采集 PLC 数据+本地处理）、平台层（存储+分析+训练）、应用层（设备监控 APP/看板）、业务层（经营决策）；数据从现场→边缘→平台→应用→人。
  3. 打交道角色：设备制造商（供货+协议）、平台提供商（接平台）、系统集成商（自己）、最终用户（交付后运维）；诉求=卖设备 / 卖平台服务 / 项目落地 / 稳定可用。
  4. 必须有工业互联网：远程监控每台发动机健康→才能按状态维护、敢承诺"可用小时"；没有远程数据→无法预知故障、不敢按小时定价。
  5. 大规模定制链路：顾客下单（业务层）→ 排产/物料优化（应用层+平台层）→ 配方/指令下发（平台→边缘）→ 柔性产线/AGV 执行（边缘+现场）→ 感知反馈（现场）→ 再感知闭环；标注 IIRA 各层流转。
