章节导言 ​

前两章我们学习了互联网基础和工业互联网整体架构。现在是时候走进工厂车间，回答一个最实际的问题了。

想象一下：下周你就要去一家汽车厂的焊装车间实习了。第一天，师傅把你带到产线旁，指着面前的设备说："FANUC 的机器人、西门子的 PLC、ABB 的焊接机器人、KEYENCE 的视觉系统、BALLUFF 的 RFID 读写头——这些设备来自五家不同的厂商，现在它们协同卡壳了，你来看看怎么解决？"

这些设备必须协同工作。机器人的每一次抓取，都发生在 PLC 发出"料架已到位"信号的精确时刻。焊接参数的每一次调整，都是因为视觉系统报告了"焊缝偏移 0.15mm"。托盘每经过一个工位，RFID 数据被读出，告诉下一台设备该做什么。

如果这些设备之间不能通信——或者通信出了问题——整条产线就停了。

这一章要回答的正是：不同厂商的设备，到底靠什么"说话"？ 你还会亲手安装 Node-RED——一个贯穿后续五个章节的核心工具——并用它模拟一次真实的工业设备通信。

环境确认：本章实践在 Ubuntu 虚拟机上安装 Node-RED 及 Modbus 节点，Windows 浏览器访问 Web 界面，Windows 安装 QModMaster 调试工具。请确认模块零环境就绪。

3.1 车间里的"巴别塔"——ISA-95 视角下的设备通信 ​

3.1.1 ISA-95 L0-L2 通信全景 ​

ISA-95 层级典型设备通信需求主流协议
L0 现场设备传感器、执行器、变频器、伺服驱动、RFID、条码枪短距离、高实时、简单数据Modbus RTU、IO-Link、HART、AS-i
L1 控制层PLC、DCS、运动控制器、机器人控制器决定性实时、周期性、同步ProfiNet、EtherCAT、CC-Link IE、EtherNet/IP、Powerlink
L2 监控层SCADA、HMI、历史服务器非周期、大数据量、可靠传输OPC UA、MQTT、HTTP/REST、ModbusTCP

关键认知：L1 控制层通信 = 现场总线/工业以太网（实时性核心）；L2 监控层通信 = IT 标准协议（互操作性核心）。两者在边缘网关/工业交换机处汇聚。[2]

3.1.2 场景导入：焊装车间的四种"语言" ​

让我们数一数这家焊装车间到底有多少种"语言"在同时使用：

设备厂商通信协议物理层角色
机器人FANUCFANUC 自有 + ProfiNet以太网/RJ45从站

痛点：PLC 是西门子家的，说 ProfiNet；视觉是 KEYENCE 家的，说 EtherCAT；传送带是三菱家的，说 CC-Link IE。它们怎么听懂彼此？

三种解决思路（贯穿本章）：

  1. 统一协议——全厂强推一种（现实难，厂商锁定强）
  2. 配翻译——协议转换网关/边缘网关做协议转发（工程常用）
  3. 通用中间层——MQTT/OPC UA 作为统一数据总线（现代架构趋势，第 5/7 章）

3.3 八大协议"华山论剑"——现场总线与工业以太网详解 ​

3.3.2 重点协议深度解析 ​

ProfiNet：西门子生态的新一代主力 ​

  • 三通道并行：标准 TCP/IP（管理/诊断）、RT 实时通道（周期数据）、IRT 等时同步通道（运动控制，μs 级抖动）
  • 硬件识别：绿色工业以太网线缆 + RJ45/M12，交换机支持 LLDP/SNMP/MRP 环网冗余
  • GSDML 文件：设备描述文件，导入 TIA Portal 即可组态，厂商无关

EtherCAT："飞读飞写"的极速列车 ​

数据帧像高速列车 → 穿过每个从站(车厢)
从站"顺手"取下自己的数据、扔上自己的数据 → 列车不停、不解耦
1
2
  • 主站发 1 个帧 → 遍历所有从站 → 返回主站，单帧完成全网数据交换
  • 1000 个从站、1ms 周期、抖动 < 1μs
  • 不需要专用交换机，普通以太网芯片即可（从站需 EtherCAT 从站控制器 ESC）
  • 为什么近年发展迅猛？ 倍福把 EtherCAT 交给 ETG 协会维护，协议"开放但需授权"（并非完全开源）。国产伺服/PLC 厂商（汇川、固高、埃斯顿等）几乎全支持，从站芯片方案成熟，全球节点数已突破 1 亿（据 ETG 官方 2026 年 4 月公布，达 1.052 亿）——从运动控制的"极速标杆"成长为工厂事实标准，与 Modbus、ProfiNet 并列为重中之重。

Modbus：最老、最简单、最开放的"通用语" ​

类比：Modbus = 快递站点对讲机——主站喊"报一下温度"（请求），从站答"25.6度"（响应）。只能一问一答，从站不能主动喊主站。

[从站地址(1B)] [功能码(1B)] [数据起始地址(2B)] [数据长度/数值(NB)] [CRC校验(2B)]

ModbusTCP 帧结构（以太网）：

[事务处理标识(2B)] [协议标识(2B)] [长度(2B)] [单元标识(1B)] [功能码(1B)] [数据...]
1

去掉了 CRC（TCP 保证可靠），加了 MBAP 头（7 字节）用于路由。

核心功能码（必会，先记 4 个）：

功能码名称数据类型读/写典型用途
0x01 (FC1)读线圈位(Coil)读开关量输出状态
0x03 (FC3)读保持寄存器字(16bit, HR)读模拟量输出、参数设定
0x04 (FC4)读输入寄存器字(16bit, IR)读模拟量输入、传感器读数
0x06 (FC6)写单个寄存器字写单参数修改

其余功能码（FC2 读离散输入 / FC5 写单线圈 / FC15 写多线圈 / FC16 写多寄存器）与 Modicon 寄存器地址约定（0x/1x/3x/4x 段），见文末“课外补充”。

实战口诀：3x 只读(传感器)、4x 读写(参数/输出)、0x/1x 开关量。Node-RED Modbus 节点用0 基址（如 40001 → 地址 0）。[1]

任务一：搭建 ModbusTCP 从站——模拟"温湿度传感器" ​

  1. 拖 Modbus Server → 类型 TCP、端口 8502、名称 温湿度传感器(从站)
  2. 拖 3 个 Modbus Response 连到 Server：
    • 当前温度：Holding Register(4x)、地址 0、值 256（代表 25.6℃，×10）
    • 设备状态：Coil(0x)、地址 0、值 1（运行中）
    • 当前湿度：Input Register(3x)、地址 1、值 275（代表 27.5%，×10）

注意：Node-RED Modbus 节点地址为0 基址，即 40001→0、30001→0、00001→0。

任务二：搭建 ModbusTCP 主站——模拟周期性轮询的"智能网关" ​

  1. 拖 Modbus Read → TCP、主机 127.0.0.1、端口 8502、FC3 读保持寄存器、地址 0、数量 1、轮询 2 秒
  2. 连 Debug 节点 → 名称 网关读取温度
  3. 部署 → Debug 面板每 2 秒打印：{"data":[256],...} → 256÷10=25.6℃

任务三：QModMaster 直连从站（跨工具验证）[5] ​

  1. Windows 下载安装 QModMaster（SourceForge/GitHub）
  2. 配置：Modbus Mode=TCP、IP=虚拟机IP、Port=8502
  3. Connect → 读保持寄存器 0 → 返回 256 ✓
  4. 写保持寄存器 0 为 300 → 观察 Node-RED Debug 面板值变为 300 ✓

任务四：制造并排查"通信故障"（核心技能） ​

故障现象制造方法排查步骤根因
连接拒绝从站端口 8502→8503 部署1. ping 通但端口不通 2. netstat -an 无监听 3. 核对两端端口一致端口不匹配
读到 0/报错从站 Response 地址改错1. 查看 Debug 原始响应 2. 核对功能码/地址/长度 3. 对照寄存器映射表地址映射错
乱码/异常值主站 FC3 改 FC4 读输入寄存器1. 抓包/看 Debug 2. 确认功能码与从站 Response 类型对应功能码不匹配
从站 ID 错误Modbus Read 单元标识改 21. 从站日志显示"未知单元标识" 2. 核对 Server/Read 单元标识一致Unit ID 不匹配

本章小结 ​

本章我们从 ISA-95 L0-L2 通信全景出发，认清了车间里"巴别塔"的现实——西门子说 ProfiNet、三菱说 CC-Link、施耐德说 Modbus、倍福说 EtherCAT、罗克韦尔说 EtherNet/IP。我们逐一拆解了 8 大主流协议的物理层、核心机制、适用场景，建立了协议选型思维。

衔接提示：

  • Modbus 解决了车间内设备互联，但从站不能主动上报、只能点对点——第 7 章我们将学习 MQTT 发布-订阅，解决设备上云、一对多解耦问题。
  • 第 4 章我们将把 Node-RED 从"通信模拟器"升级为边缘计算网关，做数据预处理、阈值判断、选择性上传。

思考与练习 ​

思考题 ​

  1. 你在实训车间看到一台设备的铭牌上标着"ProfiNet"，网线接口是 RJ45，网线外套是绿色的。请说出这个协议是哪家公司的，它和紫色的 Profibus 线缆有什么不同。

  2. 如果你要为一个简单的温湿度传感器设计通信方案，要求成本最低、开发最简单、任何品牌的 PLC 都能读取它的数据。你会选择哪种协议？说明理由。

  3. 一台 PLC 正在控制传送带的启停（L1），同时把产量计数发给 SCADA 系统（L2）。按照 ISA-95 模型，这台 PLC 同时和哪两层在交互？

  4. 在今天的实验中，Modbus Server 端口从 8502 改成 8503 后通信中断了。这和"打电话拨错号码"有什么相似之处？现场排查"通信不通"时，你会最先检查哪三个参数？

选择题 ​

  1. ISA-95 模型中，PLC 属于哪一层？ A. L0　B. L1　C. L2　D. L3

  2. 以下哪种协议的物理层不是以太网（RJ45）？ A. ProfiNet　B. EtherCAT　C. Profibus　D. CC-Link IE

  3. EtherCAT 实现高速通信的核心机制是？ A. 主站逐个轮询　B. "飞读飞写"，帧不停留　C. 使用光纤　D. 并联在交换机上

  4. 以下哪种协议是完全开放、免费的？ A. ProfiNet　B. EtherCAT　C. Modbus　D. CC-Link IE

  5. Modbus RTU 使用什么物理层标准？ A. 以太网　B. RS-485　C. 光纤　D. WiFi

  6. 在 Modbus 协议中，"线圈（Coil）"的含义是？ A. 16位寄存器　B. 单比特开关量　C. 只读模拟量　D. 可执行代码

  7. CC-Link IE 的环形拓扑最大的优势是什么？ A. 布线最短　B. 成本最低　C. 任意点断线不中断通信　D. 速度最快

  8. 某油田有数千个偏远井口的传感器，需要把数据回传到数据中心，最适合的通信方案是？ A. ProfiNet 现场总线　B. 4G/5G 无线回传　C. RS-485 串口　D. CC-Link IE 环网

判断题 ​

  1. （ ）ProfiNet 和 Profibus 都是西门子公司的通信协议。
  2. （ ）EtherCAT 使用普通 RJ45 网线和标准以太网物理层。
  3. （ ）Modbus 协议中，从站设备可以主动向主站发送报警信息。
  4. （ ）在工业环境中使用屏蔽双绞线可以降低电磁干扰。
  5. （ ）M12 圆形连接器因其防尘防水性能常用于恶劣环境。
  6. （ ）VPN 的作用是在公用网络上建立加密隧道。
  7. （ ）Modbus 的"输入寄存器"是只读的，不能被外部写入。
  8. （ ）Node-RED 是一个商业软件，需要购买许可证。
  9. （ ）npm 是 Node.js 生态的软件包管理器。
  10. （ ）DeviceNet 的物理层基于工业以太网标准。

习题答案 ​

选择题答案：1-B　2-C　3-B　4-C　5-B　6-B　7-C　8-B

简要解析：① PLC 属 L1 控制层；② Profibus 是 RS-485 串行，不是以太网；③ EtherCAT 靠"飞读飞写"单帧遍历；④ Modbus 完全开放免费；⑤ Modbus RTU 走 RS-485；⑥ 线圈=单比特开关量；⑦ CC-Link IE 环形断线不中断；⑧ 油田偏远井口用 4G/5G 无线回传。

判断题答案： 1.（√）ProfiNet 与 Profibus 均为西门子主导、PI 组织管理的协议。 2.（√）EtherCAT 用标准以太网物理层（RJ45/双绞线）。 3.（×）Modbus 是主从问答制，从站不能主动上报，只能等主站问。 4.（√）屏蔽双绞线抗电磁干扰，工业环境常用。 5.（√）M12 圆形连接器 IP67 防尘防水，用于恶劣环境。 6.（√）VPN 在公用网络上建立加密隧道。 7.（√）输入寄存器（3x）只读，写入用保持寄存器（4x）。 8.（×）Node-RED 是开源免费软件（OpenJS 基金会项目）。 9.（√）npm 是 Node.js 的包管理器。 10.（×）DeviceNet 基于 CAN 总线，不是以太网。

思考题参考要点：

  1. ProfiNet 是西门子/PI 的工业以太网协议（绿色线）；Profibus 是老款 RS-485 总线（紫色线），两者同门但换代关系，ProfiNet 实时性/带宽更强。
  2. 选 Modbus：完全开放免费、任意品牌 PLC 可读、简单可靠、成本最低。
  3. PLC 同时与 L1（控制传送带）和 L2（把产量发给 SCADA）两层交互——一台设备可跨层。
  4. 端口从 8502→8503 通信中断，类比"打电话拨错号码"（端口=号码）。排查先看三参数：IP、端口、单元标识（Unit ID），再查地址/功能码。

完整功能码表（8 个） ​

功能码名称数据类型读/写典型用途
0x01 (FC1)读线圈位(Coil)读开关量输出状态
0x02 (FC2)读离散输入位(DI)读开关量输入状态
0x03 (FC3)读保持寄存器字(16bit, HR)读模拟量输出、参数设定
0x04 (FC4)读输入寄存器字(16bit, IR)读模拟量输入、传感器读数
0x05 (FC5)写单个线圈位写单点控制
0x06 (FC6)写单个寄存器字写单参数修改
0x0F (FC15)写多个线圈位组写批量开关
0x10 (FC16)写多个寄存器字组写批量参数下发

Modicon 寄存器地址约定（0 基址 vs 1 基址） ​

  • 线圈：0xxxx (1-9999) → FC1/5/15
  • 离散输入：1xxxx (10001-19999) → FC2
  • 输入寄存器：3xxxx (30001-39999) → FC4
  • 保持寄存器：4xxxx (40001-49999) → FC3/6/16

为什么要知道：实训接 PLC/仪表时，厂家手册常写 “40001” 或 “3x” 这类地址——本节就是教你怎么读懂的；Node-RED 节点统一用 0 基址，换算关系：40001 → 地址 0。
