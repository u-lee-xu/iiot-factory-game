章节导言 ​

每天，当你打开手机刷短视频、用微信和同学聊天、或者在淘宝下单买东西时，一个覆盖全球的巨大网络正在为你服务——这就是互联网。从你指尖触碰屏幕的那一刻起，你的请求便被分割成一个个小包裹（数据包）。这些小包裹就像分头寄出的快递，沿着光纤、海底电缆一站站接力传递，最终抵达"工厂"（服务器：存放网页、处理请求的地方），"工厂"处理完后再把结果送回你的眼前。整个过程，通常就在几十到几百毫秒内完成。

可你有没有想过：这些数据包怎么知道该往哪走？服务器远在千里之外，你的手机是怎么准确找到它的？为什么有时候输入网址却打不开网页，而别人却能打开？互联网是怎么从无到有长成今天这个规模的？

这些问题，都可以在这一章找到答案。我们会一起了解互联网半个世纪的发展脉络，理解数据包在网络中逐跳转发的原理，并搞懂 IP 地址、子网掩码、网关、DNS、防火墙这些概念到底是怎么回事——不背定义，而是配合动手操作，在 Windows 和 Ubuntu 两个系统里敲一遍常用的网络诊断命令，亲眼看看数据是怎么跑的。你在模块零搭好的那个"工位"——Ubuntu 虚拟机——正好派上用场：接下来的每一章，你都要在它上面动手。

环境确认：本章实践需使用模块零已搭建的 Windows + Ubuntu 双环境。若尚未通过模块零验收，请先完成。

1.2 协议分层：快递公司的分工秘密 ​

1.2.1 为什么要分层？ ​

类比：寄快递从"下单→打包→运输→派送→签收"，每个环节只管自己的事，不关心其他环节细节。网络协议分层同理——复杂系统通过分层分工实现高效运转。

问题不分层后果分层收益
修改一个功能全系统重写只改对应层
新增硬件类型重写所有软件只适配网络接口层
跨厂商互通专有协议孤岛标准接口互操作
教学/排错无从下手逐层定位

1.2.2 TCP/IP 四层模型（本教材主用） ​

层级名称核心职责典型协议/设备类比
4应用层为用户提供网络服务接口HTTP、DNS、DHCP、SMTP快递"业务员"（面对客户）
3传输层端到端可靠/不可靠传输TCP、UDP快递"干线运输"（城际干线）
2网络层寻址、路由、分片重组IP、ICMP、路由器快递"分拣调度"（路由规划）
1网络接口层物理传输、帧封装、MAC寻址（ARP 也工作在这一层）以太网、Wi-Fi、网卡、交换机、ARP快递"末端派送"（最后一公里）

1.3 核心协议与机制逐层拆解 ​

1.3.1 网络接口层：MAC 与 ARP ​

  • MAC 地址：烧录在网卡 ROM 中的 48 位物理地址（如 00:1A:2B:3C:4D:5E），全球唯一，通常不可变。
  • ARP 协议：IP → MAC 解析。主机想发包给同网段 IP，先广播"谁是 192.168.1.5？"，目标主机单播回复 MAC。
  • 以太网帧结构：[目标MAC | 源MAC | 类型 | 数据 | FCS]

[图1-3 数据封装过程——俄罗斯套娃类比图]

类比：MAC = 身份证号（终身不变），IP = 住址（搬家就变）。ARP = "大喊一声：住在 192.168.1.5 的人，你的身份证号是多少？"

[图1-4 MAC 与 ARP——"身份证号 vs 住址"类比图]

一句话记住：MAC=身份证号（终身不变），IP=住址（搬家就变），ARP=喊一声问身份证号。[2]

1.3.2 网络层：IP、子网掩码、网关、ICMP ​

概念定义关键点
IPv4 地址32 位，点分十进制A/B/C 类 + 私有地址段（10/172.16-31/192.168）
子网掩码区分网络位/主机位与运算得网络地址：IP & Mask = NetID
默认网关本网段通往外部的出口通常是路由器 LAN 口 IP
NAT私有 IP ↔ 公网 IP 转换缓解 IPv4 枯竭，家用路由器核心功能
ICMP差错报告与诊断ping = ICMP Echo Request/Reply

私有地址段速记：10.x.x.x（1 个 A 类）、172.16~31.x.x（16 个 B 类）、192.168.x.x（256 个 C 类）

一句话记住：IP 是门牌号，子网掩码划“小区”（哪几位算小区号），网关是小区大门（出小区必须走它），ICMP 是“敲门声”（ping 敲一下问在不在）。[2]

1.5.1 防火墙核心概念 ​

维度说明

为什么两台机器能"对话"？ 因为模块零里我们把虚拟机设成了桥接模式——它和 Windows 在同一个网段（192.168.1.x）。同一网段内，ping 会先用 ARP 找到对方的 MAC（见 1.3.1 节），再发出 ICMP 探测包。换句话说，你亲手演示了第 1.3 节的 ARP + ICMP 原理——不靠背，靠亲眼看见。

本章小结 ​

本章我们从互联网发展脉络（全球+中国）出发，理解了 TCP/IP 四层模型与 OSI 七层对照，逐层拆解了 MAC/ARP、IP/子网/网关/NAT/ICMP、TCP/UDP、DNS/DHCP/HTTP 等核心协议机制，认知了接入/城域/骨干三级网络架构与 ISP 分层，建立了防火墙入站/出站规则与家用/工业防火墙差异的安全认知。

在实践环节，我们先通过 1.6 轻实践 0（双环境命令对照 + 小网 ping 通）建立了第一个“我能行”的正反馈，再在 Windows 和 Ubuntu 双环境完成了 IP 配置、连通性诊断、防火墙规则操作——这些是后续所有章节实践的基础技能包。

衔接提示：第 2 章我们将把视角从"互联网连接人/计算机"转到"工业互联网连接设备/系统"，核心模型从 TCP/IP 四层切换到 IIRA 四层（边缘/平台/应用/业务），但分层思维完全一脉相承。

  1. 以下哪个 IP 地址属于私有地址？ A. 119.29.29.29 B. 192.168.1.1 C. 202.108.22.5 D. 1.1.1.1

  2. TCP 协议与 UDP 协议的主要区别是？ A. TCP 更快，UDP 更可靠 B. TCP 面向连接、可靠传输；UDP 无连接、不保证送达 C. TCP 用于视频直播，UDP 用于网页浏览 D. 两者功能完全一样，只是名字不同

  3. DNS 的作用是？ A. 加密网络数据 B. 分配 IP 地址 C. 将域名转换为 IP 地址 D. 阻止病毒入侵

  5. 防火墙的出站规则控制的是？ A. 从外部网络进入本机的流量 B. 从本机发往外部网络的流量 C. 局域网内部的流量 D. 无线信号的强度

判断题 ​

  1. （ ）127.0.0.1 是一个公网 IP 地址。
  2. （ ）HTTPS 比 HTTP 更安全，因为传输的数据经过了加密。
  3. （ ）子网掩码决定了一个 IP 地址属于哪个网段。
  4. （ ）UDP 协议在发送数据前需要先建立连接（三次握手）。
  5. （ ）防火墙只需要设置入站规则，出站规则没有必要。
  6. （ ）ping 命令使用的是 ICMP 协议。
  7. （ ）ARP 协议的作用是将 MAC 地址转换为 IP 地址。
  8. （ ）同一台服务器上，Web 服务（端口 80）和 FTP 服务（端口 21）可以同时运行。
  9. （ ）IPv6 的地址空间比 IPv4 大得多，可以解决地址耗尽的问题。
  10. （ ）在工厂里，工业设备通常使用 DHCP 自动获取 IP 地址。

习题答案 ​

选择题答案：1-B　2-B　3-C　4-C　5-B　6-C　7-B　8-B　9-B　10-B　11-B　12-A

简要解析：① 私有地址只有 192.168.x.x；② TCP 面向连接/UDP 无连接；③ DNS 把域名翻译成 IP；④ IP 通、域名不通 = DNS 问题；⑤ 出站规则管"本机→外部"；⑥ 网络层协议是 IP；⑦ MAC 烧录在网卡、IP 可配置；⑧ DHCP 自动分配网络参数；⑨ 每层在数据前加本层头部；⑩ ARP 把 IP 解析成 MAC；⑪ NAT 把私有 IP 转公网 IP；⑫ 先 DNS 拿地址、再 TCP 握手建连接、然后发 HTTP 请求。

判断题答案： 1.（×）127.0.0.1 是回环地址（指本机），不是公网 IP。 2.（√）HTTPS 对传输数据做了 TLS 加密。 3.（√）子网掩码决定一个 IP 属于哪个网段。 4.（×）UDP 无连接，发送前不握手；三次握手是 TCP 的行为。 5.（×）出站规则同样必要（防止本机进程偷偷外联）。 6.（√）ping 用的就是 ICMP 的 Echo 请求/应答。 7.（×）ARP 是 IP→MAC；反向解析 MAC→IP 用的是 RARP/邻居表（一般不用）。 8.（√）不同端口（80 与 21）互不冲突，可同时运行。 9.（√）IPv6 128 位地址空间远大于 IPv4，可解决地址枯竭。 10.（×）工业设备通常配置静态 IP 以保证确定性，不依赖 DHCP。

思考题参考要点：

  1. 分层让每层各司其职、接口固定：改一层不动全系统（类比快递：下单/打包/干线/派送各管一段，换快递公司只改最外层）。
  2. 宿舍路由器给手机分配 192.168.x.x（私有 IP）；验证：ipconfig 看本机网段、对比手机流量时的公网出口 IP。
  3. 可能原因：本机 hosts 文件被改、路由器 DNS 被改、DNS 缓存污染；排查：查 hosts、把 DNS 换成 119.29.29.29 再试、nslookup 对比多个 DNS。
  4. 公共 WiFi 风险：中间人窃听、钓鱼热点、明文流量被嗅探；防护：不连来路不明的 WiFi、优先 HTTPS、必要时走 VPN、不在公共 WiFi 登录网银等敏感账号。
  5. 综合链路：DNS 解析（域名→IP）→ TCP 三次握手（建立可靠连接）→ 发送 HTTP 请求（带路径与参数）→ 服务器返回响应 → 浏览器解析渲染；涉及应用层(DNS/HTTP)、传输层(TCP)、网络层(IP) 协作。
