教师用书 第3章 工业互联网网络互通 ​

一、本章教学目标 ​

知识目标 ​

  1. 理解 ISA-95 五层模型（L0~L4）的层级结构和各层关心的核心问题
  2. 掌握六种主流工业通信协议（ProfiNet、Profibus、EtherCAT、CC-Link IE、Modbus、EtherNet/IP）的特点和适用场景
  3. 理解 ISA-95 与 IIRA 两套模型的区别与联系
  4. 了解 Modbus 协议的四类寄存器（线圈、离散输入、保持寄存器、输入寄存器）和常用功能码
  5. 理解工业协议与消费互联网协议在设计理念上的根本差异

技能目标 ​

  1. 能在 Ubuntu 虚拟机上独立安装 Node-RED 并配置开机自启
  2. 能通过浏览器访问 Node-RED Web 界面并安装社区节点
  3. 能用 Node-RED 搭建 ModbusTCP 从站（模拟传感器）和主站（模拟网关）
  4. 能使用 QModMaster 调试工具手动读写 Modbus 寄存器
  5. 能诊断"通信参数不匹配"类常见故障（端口、IP、从站 ID）

素养目标 ​

  1. 通过乌克兰电网案例理解工业协议的严谨性，培养工程安全意识
  2. 通过协议"一句话口诀"训练精准表达能力
  3. 通过设备"语言不通"的场景理解跨厂商集成的现实挑战

三、各节教学实施建议 ​

第1次课：3.1 设备怎么对话 + ISA-95 ​

教学导入（10分钟） ​

从学生熟悉的场景切入：手机和电脑都能联网是因为用了同样的协议（WiFi + TCP/IP）。然后提出问题：为什么工厂里的 FANUC 机器人、SIEMENS PLC、ABB 焊接机之间不能直接"打电话"？

展示图 3-1（焊装车间多协议设备示意图）的实际照片或网络拓扑图，让学生直观感受"语言不通"的现场。

知识讲解（60分钟） ​

第一部分：焊装车间的四种语言（20分钟）

按照教材 3.1 节的顺序讲，重点：

  1. 七个设备、四种协议的表格，让学生在笔记本上记录
  2. 三种解决思路（统一协议/协议网关/通用中间层），分别举例
  3. 强调"统一协议在现实中永远无法完全实现"——引出学多种协议的必要性

第二部分：ISA-95 五层地图（40分钟）

这是本章最核心的理论知识点，重点讲清楚：

  1. 每一层"关心什么问题"——用具体例子说明

    • L0："现在温度75.3℃"（传感器回答"是多少"）
    • L1："如果>80℃，关闭加热器"（PLC回答"该做什么"）
    • L2："3号线所有设备状态——中控大屏看全局"（SCADA回答"整体什么样"）
    • L3："这批订单做到哪了？"（MES回答"生产进行到哪了"）
    • L4："这个月赚了还是亏了？"（ERP回答"经营状况如何"）

  2. 用类比帮助记忆：

    • L0 = 人的感官（眼睛看、耳朵听）
    • L1 = 人的大脑（思考、判断）
    • L2 = 主管的平板电脑（看整个车间）
    • L3 = 车间主任的电脑（管生产计划）
    • L4 = 老板的办公室（管经营）

  3. ISA-95 与 IIRA 的对应关系（15分钟）

    • ISA-95 是"纵向"——从传感器到 ERP（垂直方向）
    • IIRA 是"横向"——从边缘到云到业务（水平方向）
    • 两者可以叠加使用，描述同一个工厂

板书建议：在黑板上画 ISA-95 五层金字塔，每层标注层级名称、典型设备、代表问题。

回顾讨论（10分钟） ​

让学生回答：

  1. "PLC 属于哪一层？SCADA 属于哪一层？"（快速点名，检验理解）
  2. "ISA-95 和 IIRA 有什么区别？"（开放讨论）

常见问题与解答 ​

问题解答
"PLC 到底属于 L1 还是 L2？"大多数 PLC 属于 L1（做控制逻辑）；如果 PLC 同时在做数据采集和上报，可能同时承担 L2 职责。现实中常有重叠。
"能不能直接把所有设备换成同一套协议？"理论上可以，现实中成本极高。新设备选型时优先考虑统一，老设备用网关过渡。
"ISA-95 和 IIRA 哪个更好用？"各有侧重。ISA-95 描述工厂内部纵向关系更清晰；IIRA 描述工业互联网整体架构更全面。两者结合使用。

第2次课：3.2 动手实践：安装 Node-RED ​

教学准备 ​

  • 确保每个学生已完成 VMware Ubuntu 虚拟机安装和网络配置（参考第1章和第2章内容）
  • 检查 SSH 连接是否正常（教师演示：Windows 终端 SSH 登录）
  • 预先下载好 node-red-contrib-modbus 节点的离线包（如网络较慢）

教学导入（5分钟） ​

Node-RED 是贯穿后续5章的核心工具，本节安装质量直接影响后续实践。本节目标：每个学生都能在浏览器里看到 Node-RED 界面。

分步演示与学生操作（75分钟） ​

任务一：安装 Node-RED（25分钟）

  1. 教师演示（10分钟）：

    • SSH 登录 Ubuntu
    • 粘贴安装命令
    • 解释 curl -sL 的含义（静默跟随重定向）
    • 强调：安装过程需要3-5分钟，中间不要断开网络

  2. 学生操作（15分钟）：跟做，教师巡视

常见问题：

  • Node.js 版本不兼容 → 脚本会自动安装正确版本，耐心等待
  • 网络中断 → 重新运行安装命令（幂等操作）

任务二：启动与开机自启（10分钟）

讲解 node-red-start 和 systemctl enable nodered 的区别：前者是手动启动，后者是开机自动启动。

任务三：Web 界面访问（15分钟）

  1. 教师演示：在 Windows 浏览器中输入 Ubuntu IP:1880
  2. 学生操作：记录自己的 Ubuntu IP，访问 Web 界面
  3. 逐一检查：确保每个学生都能看到 Node-RED 编辑界面

教学重点：Node-RED 的三个区域（左侧节点面板/中间 Flow 编辑区/右侧信息面板），让学生在纸上画出来并标注名称。

任务四：安装 Modbus 节点（15分钟）

  1. 教师演示：通过 Manage palette 安装 node-red-contrib-modbus
  2. 强调：搜索时输入完整名称，不要只输入"modbus"
  3. 学生操作，教师巡视

任务五：ISA-95 关联节点（10分钟）

这是本节的微环节思政点：

  1. 用注释节点（Comment）画出 ISA-95 五层
  2. 用线连接，模拟数据流动方向
  3. 讲解：工具安装不是纯技术操作，要和理论结合

回顾讨论（5分钟） ​

让学生展示自己画的 ISA-95 节点图，互相评价。

常见问题与解答 ​

问题解答
"安装后浏览器打不开 1880 端口"先用 node-red-status 确认服务运行；再检查防火墙 sudo ufw status；再检查端口 `netstat -tlnp
"Modbus 节点找不到"安装完成后需要刷新页面（Ctrl+R），节点才会出现在左侧面板
"节点安装失败"检查网络连接；尝试用 npm 手动安装：cd ~/.node-red && npm install node-red-contrib-modbus

第3次课：3.3 六大协议华山论剑 ​

教学导入（5分钟） ​

快速回顾：3.1 节的三种解决思路（统一协议/协议网关/通用中间层），引出六种主流协议。

知识讲解（70分钟） ​

六种协议讲解顺序（建议按教材顺序）：

协议归属厂商核心特点一句话口诀
Profibus西门子老款总线，紫色线紫色线=老款
ProfiNet西门子新款工业以太网，绿色线绿色线=新款
EtherCAT倍福飞读飞写，极快快=运动控制
CC-Link IE三菱环形冗余日系=环形冗余
Modbus施耐德(开放)最老最开放免费=最低门槛
EtherNet/IP罗克韦尔北美主流CIP=北美

每种协议的讲解要点（每个8-10分钟）：

  1. Profibus/ProfiNet（15分钟）

    • 重点区分"同一厂商的两代产品"
    • 物理层对比（RS-485 vs 以太网）
    • 一句话口诀：紫色线=老款，绿色线=新款

  2. EtherCAT（10分钟）

    • "飞读飞写"是理解核心，用图示讲解数据帧穿过从站的过程
    • 类比：数据帧像一辆公交车，每站停车上（下）客，Bus Stop Network
    • 强调：物理层和普通以太网完全一样（所以成本低）

  3. CC-Link IE（8分钟）

    • 环形拓扑的冗余机制是亮点
    • 日系工厂（丰田、三菱）标配

  4. Modbus（20分钟）

    • 四种寄存器类型（线圈/离散输入/保持寄存器/输入寄存器）是重点
    • 用功能码表格让学生记忆5个最常用的码
    • 强调最大优势（免费开放）和最大局限（从站不能主动通信）

  5. Powerlink/DeviceNet/EtherNet/IP（7分钟）

    • 简要带过，作为知识面拓展
    • EtherNet/IP 是罗克韦尔的主推，注意和 ProfiNet 的对比

  6. 五种传输介质（10分钟）

    • RJ45工业级/DB9/M12/屏蔽双绞线/工业交换机
    • 实物展示（如果有）：让学生触摸 RJ45 工业头和普通头的区别

课程思政融入（10分钟） ​

乌克兰电网案例的讲解要点：

  1. 描述事件经过：攻击者利用 IEC 104 协议漏洞，远程操控断路器
  2. 引导学生思考：消费互联网被攻击最多是"网页打不开"，工业系统被攻击是"工厂爆炸"
  3. 引出工程伦理：协议工程师的一行代码可能关系到生命安全
  4. 讨论问题：为什么工业协议对"确定性"和"可靠性"要求远高于消费协议？

回顾讨论（5分钟） ​

让学生快速回答：

  1. "哪几种协议用 RJ45 网线？"（ProfiNet/EtherCAT/CC-Link IE/EtherNet/IP）
  2. "Modbus 最大的局限是什么？"（从站不能主动通信）
  3. "哪种协议的物理层和普通以太网一样？"（EtherCAT）

常见问题与解答 ​

问题解答
"ProfiNet 和工业以太网是一回事吗？"不完全相同。工业以太网是泛指所有基于以太网技术的工业协议；ProfiNet 是其中一种具体实现，还有 EtherCAT、EtherNet/IP 等。
"Modbus RTU 和 ModbusTCP 能直接通信吗？"需要一个协议转换网关，不能直接通信。但两者使用相同的寄存器地址规则，转换相对简单。
"为什么 EtherCAT 这么快？"不是因为带宽高（和普通以太网一样是100Mbps），而是因为处理方式高效——帧不用停下来等待每个从站处理，而是"飞过"每个从站时同步读写。

第4次课：3.4 动手实践：ModbusTCP 通信实战 ​

教学准备 ​

  • 确保每位学生已完成 3.2 节的 Node-RED 安装
  • 预先在教师机上安装 QModMaster，用于课堂演示
  • 打印任务单，确保学生动手时有记录表可填

教学导入（5分钟） ​

回顾 Modbus 协议的四类寄存器和功能码，为实验做知识准备。

分步演示与学生操作（75分钟） ​

任务一：搭建 ModbusTCP 从站（25分钟）

这是本节最关键的步骤：

  1. 讲解 Modbus Server 节点的配置参数（类型/端口/从站ID）
  2. 演示配置三个寄存器：温度/状态/湿度
  3. 学生操作，教师巡视
  4. 重点讲解：为什么用 8502 而不是默认的 502？（避免权限问题）

验证方法：点击"完成"后 Server 节点显示"已连接"状态。

任务二：搭建 ModbusTCP 主站（20分钟）

  1. 讲解轮询机制：主站每2秒自动读取一次寄存器
  2. 演示 Modbus Read 节点的配置
  3. 学生操作，点击部署
  4. 观察 Debug 面板的输出，理解"轮询"的含义

验证方法：Debug 面板每2秒输出新数据。

任务三：QModMaster 直连（15分钟）

这是对比理解的关键环节：

  1. 教师演示：连接配置、读取寄存器 0（应为256）
  2. 学生操作：在寄存器 0 写入 300，观察 Node-RED Debug 面板的变化
  3. 讲解：QModMaster 相当于一个"手动控制器"，和主站一样在访问同一个从站

任务四：制造并排查故障（15分钟）

这是培养故障排查能力的核心环节：

  1. 让学生故意把端口改为 8503，部署，观察"Connection refused"
  2. 改回 8502，部署，观察恢复
  3. 引导学生思考：和"打电话拨错号码"的类比

故障排查引导（10分钟） ​

当"通信不通"时，按以下顺序排查：

  1. 物理层：网线是否插好？（最容易被忽略）
  2. IP 层：两端 IP 是否在同一网段？（ping 命令测试）
  3. 端口层：端口号是否一致？（本次实验中最常见的错误）
  4. 从站 ID：主站配置的从站 ID 是否和从站一致？
  5. 防火墙：sudo ufw status 检查防火墙状态

回顾讨论（5分钟） ​

让学生复述 ModbusTCP 通信的三个组成部分（从站/主站/调试工具）及其作用。

常见问题与解答 ​

问题解答
"Modbus Read 节点一直显示黄色（未连接）"先确认 Modbus Server 已部署（显示绿色）；再检查主机 IP 是否为 127.0.0.1；再检查端口号是否一致
"QModMaster 读取不到数据"检查 QModMaster 的 Modbus Mode 是否设为 TCP；检查 IP 和端口；尝试用 ping 命令先测试网络连通性
"Debug 面板显示 NaN"说明寄存器值解析格式不对，检查功能码是否匹配（FC3 对应 Holding Register）

常见错误预判 ​

错误预防措施
端口号记错（502/8502混淆）强调实验用 8502 的原因；让学生在任务单上记录端口号
Modbus Read 节点功能码选错复习五种功能码对应的数据类型；强调 FC3 对应 Holding Register
忘记点击"部署"每次修改参数后提醒学生；解释"部署=保存并运行"的含义

六、思考与练习参考答案 ​

选择题 ​

题号答案解析
1BPLC 的核心职责是控制逻辑（L1），不是感知（L0）也不是监控（L2）
2CProfibus 使用 RS-485（DB9接头），其余五种均基于以太网（RJ45）
3BEtherCAT 的"飞读飞写"机制是其高速的核心；帧像火车穿过每个从站，从站不解包直接读写
4CModbus 是唯一完全免费开放的协议；ProfiNet/EtherCAT/CC-Link IE 均需厂商认证
5BModbus RTU 基于 RS-485 串行总线；ModbusTCP 才用以太网
6B线圈（Coil）是单比特（1位）开关量，可读可写；寄存器是16位（2字节）
7CCC-Link IE 环形拓扑任一点断线可自动切换为两条线型网络继续工作，是其最大优势
8DWi-Fi 6E 是 WiFi 标准，不是 5G 的工业特性；eMBB/mMTC/uRLLC 均是 3GPP 定义的 5G 特性

判断题 ​

题号答案解析
1√ProfiNet 和 Profibus 均由西门子主导开发，属于西门子生态
2√EtherCAT 在物理层使用标准以太网和 RJ45 接口，这让其硬件成本低且兼容性好
3×Modbus 通信采用主从模式，从站不能主动向主站发送数据；报警需由主站轮询检测
4√屏蔽双绞线（STP）通过铝箔或编织网屏蔽层减少电磁干扰，是工业环境的首选
5√M12 连接器符合 IEC 61076-2-101 标准，防护等级可达 IP67，常见于传感器和现场设备
6√VPN（Virtual Private Network）通过加密隧道技术在公用网络上建立虚拟专用网络
7√Input Register（功能码 FC04）只读；Holding Register（FC03/FC06）可读写
8×Node-RED 是 IBM 开发并完全开源的项目（Apache 2.0 许可证），完全免费
9√npm（Node Package Manager）是 Node.js 生态的默认包管理器，Node-RED 依赖它安装节点
10×DeviceNet 基于 CAN 总线物理层（不是工业以太网），适合北美旧款设备；EtherNet/IP 基于工业以太网

思考题参考答案 ​

第1题： ProfiNet 是西门子新一代工业以太网协议，使用绿色工业网线（RJ45接口），支持微秒级实时通信；Profibus 是西门子老款现场总线协议，使用紫色屏蔽双绞线（DB9接口），RS-485 物理层，最高 12 Mbps。两者都是西门子家的，但 ProfiNet 是 Profibus 的"升级换代"产品。

第2题： 选择 Modbus TCP（基于以太网）或 Modbus RTU（基于 RS-485）。理由：① 完全免费，任何 PLC 都原生支持；② 实现门槛最低，几行代码即可完成开发；③ 最开放，几乎所有传感器和仪表厂商都支持 Modbus。

第3题： 这台 PLC 同时与 L1（控制传送带启停）和 L2（向 SCADA 上报数据）进行交互——在 L1 层它是控制器，在 L2 层它是数据采集点。

第4题： 和"打电话拨错号码"相似之处：端口号就像电话号码，错了就找不到目标设备。最先检查的三个参数：① 端口号（8502 还是 8503？）；② IP 地址（127.0.0.1 还是其他？）；③ 从站 ID（从站配置的 ID 和主站请求的 ID 是否一致？）。
