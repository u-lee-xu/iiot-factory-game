第5章 工业互联网平台（教师用书） ​

本章定位：从边缘侧走向云端。第4章我们在边缘侧处理数据，本章数据上传到云端——工业互联网平台。我们将学习平台的概念与三层能力、中国平台版图，以及支撑平台应用部署的核心技术Docker容器。 课时安排：10课时（理论6 + 实践4） 学情分析：学生对手机应用商店很熟悉，但对工业互联网平台陌生；"三层能力"和"边缘vs平台分工"需要结合第4章已有认知来讲解；中国平台版图涉及多家企业，信息量大，需要用"基因"线索串联；Docker是全新概念，需要大量类比帮助理解；实践环节Docker安装可能遇到网络问题，需要提前准备镜像源。

一、本章教学目标 ​

知识目标 ​

  1. 理解工业互联网平台的概念、作用和典型架构
  2. 理解平台三层能力（设备连接与管理、数据存储与分析、应用开发与托管）
  3. 了解中国工业互联网平台版图（"互联网向下做"vs"制造业向上做"两类基因）
  4. 了解"双跨"平台的含义和我国主要的双跨平台
  5. 理解Docker容器的概念、优势和核心组件
  6. 了解镜像、容器、仓库的关系
  7. 理解Docker容器与虚拟机的区别
  8. 了解Docker Compose多容器编排的基本概念

技能目标 ​

  1. 能在Ubuntu上安装Docker
  2. 能使用Docker命令拉取、运行、停止、删除容器
  3. 能用Docker部署Nginx网页服务器
  4. 能用Docker部署Node-RED，并与原生安装进行双开对比
  5. 能将容器中的数据持久化到本地（卷映射）

素养目标 ​

  • 平台思维：理解平台如何整合资源、降低门槛
  • 开放共享意识
  • 自主创新意识：了解我国工业互联网平台的发展成就
  • 制造强国战略意识

二、课时分配与教学安排 ​

课次课时内容教学类型重点/难点
第1次课2h5.1 平台概念（应用商店类比+定义+思政+标识解析）+ 5.2 三层能力（向下/中间/向上）理论重点：平台三层能力；难点：时序数据库的概念、边缘与平台的分工逻辑
第2次课2h5.2 树根互联案例 + 5.3 中国平台版图（四家平台基因+双跨平台）理论重点：两类平台基因的差异；难点：理解"互联网向下做"与"制造业向上做"的本质区别
第3次课2h5.4 Docker核心概念（集装箱类比+Docker vs VM+三个核心概念+常用命令+工业场景价值）理论重点：镜像与容器的区别、Docker vs VM；难点：容器共享内核的隔离机制
第4次课2h5.5 实践：Docker入门（安装+Hello World+Nginx）实践重点：Docker安装、端口映射；难点：权限问题、端口映射概念
第5次课2h5.6 实践：Docker部署Node-RED（双开对比+启停删除）实践重点：双开对比理解容器化优势；难点：1881:1880端口映射避免冲突

说明：教材内容从原来的4节扩展为6节，知识密度显著增加（新增三层能力详解、中国平台版图、Docker vs VM对比、Nginx实践、双开对比等），课时从8课时调整为10课时。如果课时紧张，5.1中的标识解析可作为课后阅读，5.3中的非核心平台（航天云网、用友精智等）可略讲。

三、各节教学实施建议 ​

5.1 手机应用商店和工业平台的共同逻辑（理论） ​

教学导入（10分钟） ​

  1. 互动提问："你们买了新手机后做的第一件事是什么？"（引导学生说出"下载APP"）
  2. 追问："为什么微信开发者不需要知道你的手机是华为还是小米？"（引出"中间层"概念）
  3. 类比迁移：手机应用商店在开发者和用户之间屏蔽了底层差异——工业互联网平台做的是同样的事，只是服务对象变成了设备、数据和工业应用

知识讲解（40分钟） ​

  1. 平台定义：引用AII白皮书定义，用通俗语言拆解——"向下连设备，向上承载应用，中间存数据、做分析"
  2. 平台的"中间层"角色：结合图5-1，强调平台不是设备本身，也不是应用本身，而是连接两者的"中间件"
  3. 平台如何降低门槛：对比"自己开发"（买服务器→招团队→开发→维护，几百万起步）vs"平台订阅"（按使用量付费，成本降90%以上），用数字说话
  4. 课程思政融入：展示卡奥斯、树根互联等自主平台的成就，讨论"为什么自主可控的平台很重要"，引导学生树立制造强国意识
  5. 标识解析与平台的衔接：标识解析负责"找到数据在哪里"，平台负责"用这些数据"——两者结合让数据跨企业流通。强调"了解即可"，不做深入展开

回顾讨论（10分钟） ​

  • 提问："用一句话说，工业互联网平台是什么？"
  • 提问："平台降低了什么门槛？降低了多少？"

常见Q&A ​

学生可能问的问题建议回答
平台和云计算是什么关系？工业互联网平台通常构建在云计算基础设施之上，但平台比"云"多了行业能力（设备接入SDK、工业协议适配、时序数据库等）
标识解析考试考吗？了解即可，不深入展开。感兴趣的同学可以课后阅读AII的标识解析白皮书
自己开发的系统算不算"用了平台"？见教材思考题1，留到章末讨论

5.2 工业互联网平台做什么：三层能力（理论） ​

教学导入（10分钟） ​

  1. 承上启下："5.1说了平台是'中间层'，那这个中间层到底提供什么能力？"
  2. 三层拆解预告：向下（连设备）、中间（存数据做分析）、向上（跑应用）

知识讲解（50分钟） ​

  1. 向下——设备连接与管理：
    • SDK、协议适配（Modbus/MQTT/OPC UA）、数字模型（数字孪生基础）、远程配置和固件升级
    • 以树根互联为例：截至2023年接入设备超120万台，覆盖工程机械、能源装备等多个领域
  2. 中间——数据存储与分析：
    • 重点讲时序数据库：工业数据带时间戳（某时刻某设备的温度/压力），时序数据库（InfluxDB、TDengine）针对这种模式深度优化
    • 对比普通数据库：查询"过去24小时某风机所有温度测点的最大值"，时序数据库快几个数量级
    • 实时流计算引擎（30秒内温度持续上升速率是否异常）+ 批处理分析引擎 + 可视化工具 + AI模型训练
  3. 向上——应用开发与托管：
    • 低代码/无代码开发工具（让非编程背景工程师也能搭建应用）
    • API网关和微服务框架（支撑专业开发团队）
    • 预告第6章：工业APP开发正是依托这一层能力
  4. 结合IIRA四层模型：平台层对应IIRA的"平台层"，下面是边缘层，上面是应用层和业务层——平台是数据从"采集"走向"变现"的枢纽
  5. 边缘与平台的分工（重点）：
    • 结合第4章已有认知，用表格对比边缘侧vs平台侧
    • 核心口诀："边缘管'现在'（实时判断），平台管'趋势'（历史分析）"
    • 边缘每秒做温度判断，但无法回答"过去半年振动趋势是否在恶化"——这需要平台的海量历史数据和机器学习模型
  6. 树根互联与三一重工案例：
    • 设备接入：每台挖掘机/泵车安装传感器和通信模块，4G/5G实时上传
    • 数据分析：海量数据汇入时序数据库，分析模型判断设备健康状态
    • 应用呈现：管理者看可视化看板，维修工收故障预警
    • 亮点："挖掘机指数"——全国数十万台挖掘机开工率反映基建活跃度，被经济学家用于预测宏观经济
    • 三一从"卖设备"转型"卖设备可用时间"的商业模式变革（呼应第2章）

回顾讨论（10分钟） ​

  • 教材中的三个回顾反思题，让学生同桌互答：
    1. 平台"三层能力"分别是什么？用一句话概括每层
    2. 边缘层和平台层如何分工？
    3. 树根互联案例中，三层能力如何形成闭环？

常见Q&A ​

学生可能问的问题建议回答
时序数据库和MySQL有什么区别？MySQL是通用关系型数据库，适合存订单、用户等业务数据；时序数据库专门为"时间戳+传感器读数"模式优化，查询聚合速度极快
边缘和平台的边界是固定的吗？不是。随着边缘网关算力增强，一些原来在平台做的分析可以下沉到边缘。5.3节会讲"云端管控、边缘执行"的协同模式
挖掘机指数真的能预测经济吗？它是侧面参考指标，不是唯一依据。但它确实比传统统计数据更实时、更客观

5.3 中国工业互联网平台的版图（理论） ​

教学导入（10分钟） ​

  1. 数据引入："中国工业互联网平台数量2023年已超过240家。这么多平台，怎么理解？"
  2. 核心线索预告：不需要记住所有平台，但需要理解一个版图逻辑——"从互联网出发向下做"和"从制造业出发向上做"

知识讲解（40分钟） ​

  1. 阿里云IoT：互联网基因，"把互联网技术向工业输出"——AI视觉做电路板缺陷检测，飞天大数据做钢铁能耗优化。一句话记住："淘宝那家公司的工业云"
  2. 华为云FusionPlant：通信+IT基因，"端到端"——从5G专网到边缘Atlas到云上AI，全栈自研。华为自身也是大型制造企业。一句话记住："造手机和基站的公司做的工业平台"
  3. 树根互联：制造业基因，从三一重工孵化，核心优势是对工程机械的深刻理解——振动分析、液压诊断、远程锁机防盗都从真实场景打磨。一句话记住："三一的挖掘机都连在上面"
  4. 海尔卡奥斯：制造业基因，大规模定制模式——用户APP定制冰箱，订单直下产线，柔性生产直发用户。连续位居双跨平台首位。一句话记住："用户定制冰箱的工厂平台"
  5. 四家平台对比表：用教材中的表格（出身/基因/一句话记住它）做课堂速记
  6. 其他平台简要提及：航天云网（军工供应链）、用友精智（ERP起家）、蘑菇物联（空压机垂直平台）——了解即可
  7. "双跨"平台：工信部从2019年起每年评选，"跨行业跨领域"，截至2025年约50家，代表国内最高水平
  8. 边缘与平台协同：主流平台都提供边缘管理能力——"云端管控、边缘执行"，工程师在平台点击"升级"，远端边缘网关软件自动更新

回顾讨论（10分钟） ​

  • 教材中的三个回顾反思题：
    1. 两类平台基因有什么不同？各举一个例子
    2. 什么是"双跨"平台？代表什么水平？
    3. 工程机械厂选平台，推荐哪一类？为什么？

常见Q&A ​

学生可能问的问题建议回答
哪类平台更好？没有绝对优劣，取决于场景。需要AI和大数据能力的选互联网基因平台，需要行业深度理解的选制造业基因平台
双跨平台考试要背哪些？记住概念（跨行业+跨领域）和代表性平台（卡奥斯、树根互联等）即可，不需要背完整名单
"云端管控、边缘执行"和第4章学的边缘计算矛盾吗？不矛盾。边缘网关仍然在本地做实时判断，只是它的软件版本和配置可以由云端统一管理——"执行在边缘，管理在云端"

5.4 Docker容器：让工业应用像手机APP一样部署（理论） ​

教学导入（10分钟） ​

  1. 场景提问："你有没有遇到过'在我电脑上能运行，在服务器上运行不了'的情况？为什么？"
  2. 引出痛点：传统部署需要"装依赖、配环境、调兼容性"三步走，换一台服务器就得重来
  3. 预告Docker：一条命令就能部署，怎么做到的？

知识讲解（55分钟） ​

  1. 集装箱类比（10分钟）：
    • 1950年代远洋运输革命：形状各异的货物→标准化集装箱，船不在乎箱子里装什么
    • Docker对软件做的事完全一样：应用+全部依赖打包成标准镜像，任何装了Docker的机器上运行结果一致
    • 结合图5-2加深印象
  2. Docker vs 虚拟机（15分钟，重点+难点）：
    • 回顾第2章VMware虚拟机：模拟完整硬件，上面装独立操作系统——"虚拟化"
    • Docker走另一条路：容器化——不模拟硬件，共享同一个Linux内核，通过命名空间和控制组实现隔离
    • 用教材对比表逐行讲解：类比（独立别墅vs标准化集装箱）、启动速度（分钟vs秒）、磁盘占用（GB vs MB）、隔离完整度（完全隔离vs进程级隔离）、适合场景
    • 工业场景强调：边缘网关上可能跑几十种软件（软PLC、数采引擎、协议转换、本地数据库、AI推理），用虚拟机算力不够，用容器共享内核资源占用小得多
  3. 三个核心概念（15分钟）：
    • 镜像（Image）：只读模板，"集装箱的设计图纸"。以Node-RED官方镜像为例：打包了Node.js运行时和完整环境
    • 容器（Container）：从镜像运行出来的实例，"按图纸造出来的集装箱"。一个镜像可以启动多个容器，彼此隔离
    • 仓库（Registry）：存放镜像的地方，"集装箱图纸的图书馆"。Docker Hub是全球最大公开仓库
    • docker pull = 从仓库下载镜像，docker run = 把镜像实例化为容器
  4. Docker常用命令速查（5分钟）：
    • 展示教材中的命令表格，让学生标记为"后续实践课的参考手册"
  5. Docker在工业场景中的价值（10分钟）：
    • 核心价值：确保边缘和云端运行完全一致的软件环境
    • 场景：10台边缘网关部署相同的数据采集软件——传统方式逐台登录安装可能装出10个略有差异的环境；Docker方式只需同一条docker run命令，环境完全一致
    • 联系5.3节："云端管控、边缘执行"模式，底层靠的就是Docker标准化打包和部署能力

回顾讨论（10分钟） ​

  • 教材中的三个回顾反思题：
    1. 镜像、容器、仓库分别对应集装箱类比中的什么？
    2. Docker容器和虚拟机的本质区别是什么？为什么工业边缘网关更倾向于用容器？
    3. 10台边缘网关部署相同软件，Docker能带来什么好处？

常见Q&A ​

学生可能问的问题建议回答
Docker能替代虚拟机吗？不能完全替代。需要运行不同操作系统（如Windows应用）时仍需虚拟机；在同一Linux上快速部署大量应用时Docker更优
容器共享内核安全吗？进程级隔离对绝大多数工业场景足够。如果需要极高安全隔离（如多租户环境），可以用Kata Containers等加强隔离的容器方案
Docker和Kubernetes是什么关系？Docker负责打包和运行单个容器，Kubernetes（K8s）负责管理大规模容器集群——可以理解为Docker是"集装箱"，K8s是"集装箱调度系统"

5.5 动手实践：Docker容器技术入门（实践） ​

实践准备（课前） ​

  1. 提前准备国内Docker镜像源（阿里云、清华源），避免课上下载太慢
  2. 提前下载好hello-world和nginx镜像，分发到学生虚拟机
  3. 确认所有学生虚拟机SSH可正常连接

任务一：安装Docker（35分钟） ​

  1. 分步演示：按教材步骤操作
  2. 重点提示：
    • 一键安装脚本 get.docker.com 适用于实验环境，生产环境需通过官方仓库安装
    • 权限问题：sudo usermod -aG docker $USER，必须退出SSH重新登录才能生效
  3. 学生操作：跟着做，教师巡视解决问题
  4. 验证安装：docker --version，看到版本号即成功

任务二：运行Hello World容器（15分钟） ​

  1. 演示运行：docker pull hello-world → docker run hello-world
  2. 讲解原理：Docker先找本地镜像，没有就去Docker Hub拉取；容器里的程序打印消息后自动退出
  3. 强调：这条消息不是Ubuntu打印的，是容器里的程序打印的——这就是隔离

任务三：运行Nginx网页服务器（40分钟） ​

  1. 拉取镜像：docker pull nginx
  2. 分步讲解参数：
    • -d：后台运行（detach），终端不被占用
    • --name mynginx：给容器取名，方便后续操作
    • -p 8080:80：端口映射——重点讲解，用"门牌号"类比：容器内部是80端口（内部门牌），主机8080端口是对外门牌，映射就是把两个门牌号关联起来
    • nginx：使用的镜像名
  3. 学生操作：运行容器，在Windows浏览器访问 http://虚拟机IP:8080
  4. 看到"Welcome to nginx!"：强调"你的Ubuntu并没有安装Nginx——Docker镜像里已经包含了完整运行环境"
  5. 练习容器操作命令：docker ps、docker logs、docker stop、docker start、docker stop && docker rm

回顾讨论（10分钟） ​

  • 提问："hello-world和Nginx容器有什么区别？"（一个运行完就退出，一个持续运行提供服务）
  • 提问："端口映射 -p 8080:80 中，哪个是主机的端口？哪个是容器的端口？"（左边主机，右边容器）

常见Q&A ​

学生可能问的问题建议回答
Docker安装后必须重新登录吗？是的，usermod -aG docker $USER 修改了用户组，必须重新登录才能生效。否则每次都要加 sudo
浏览器访问不了8080端口怎么办？三步排查：① docker ps 确认容器在运行；② sudo ufw allow 8080 开放防火墙；③ 确认使用的是虚拟机IP而非localhost
Nginx的80端口和主机的80端口冲突吗？不冲突。容器内部有自己的网络命名空间，容器内的80端口和主机的80端口互不影响

5.6 动手实践：在Docker中部署Node-RED（实践） ​

实践准备（课前） ​

  1. 确认学生Docker已安装好
  2. 提前下载好nodered/node-red镜像
  3. 确认第3章原生安装的Node-RED仍在运行（占用1880端口）

任务一：用Docker运行Node-RED（25分钟） ​

  1. 拉取镜像：docker pull nodered/node-red
  2. 运行容器：docker run -d --name mynodered -p 1881:1880 nodered/node-red
  3. 重点讲解端口映射：为什么用 1881:1880 而不是 1880:1880？——因为原生安装的Node-RED已经占了主机的1880端口，Docker容器的Node-RED映射到1881避免冲突
  4. 访问验证：浏览器打开 http://虚拟机IP:1881，看到全新空白的Node-RED界面

任务二：双开对比——原生vs容器（25分钟） ​

  1. 同时打开两个浏览器标签页：
    • 标签页A：http://虚拟机IP:1880（原生安装，有之前做的Modbus Flow和边缘数据处理流）
    • 标签页B：http://虚拟机IP:1881（Docker容器，全新空白）
  2. 引导学生关注对比表（教材中的5个维度）：
    • 安装方式：官方脚本 vs 一条docker run
    • 安装耗时：3-5分钟 vs 镜像拉取后几秒
    • 环境隔离：依赖装在Ubuntu上 vs 封装在容器内
    • 数据位置：Ubuntu文件系统 vs 容器内部（删了就没了）
    • 删除重装：可能残留 vs docker rm彻底清除，docker run全新干净
  3. 核心结论：容器化部署的核心优势——秒级启停、环境隔离、删除即清除

任务三：容器的启停和删除（20分钟） ​

  1. 停止容器：docker stop mynodered，访问1881端口显示"无法连接"
  2. 重新启动：docker start mynodered，之前在容器Node-RED中做的修改还在
  3. 完全删除：docker stop mynodered && docker rm mynodered
  4. 重建全新容器：docker run -d --name mynodered -p 1881:1880 nodered/node-red——和之前完全一样的环境，全新空白
  5. 联系工业场景：应用升级出问题可秒级回滚；10台网关部署相同软件只需同一条命令

回顾讨论（10分钟） ​

  • 提问："容器删除后数据去哪了？"（没了——引出课后拓展中的数据持久化/卷映射）
  • 提问："双开对比中，哪种方式更适合在10台边缘网关上部署？为什么？"

常见Q&A ​

学生可能问的问题建议回答
1880和1881端口上的是同一个Node-RED吗？不是。1880是原生安装在Ubuntu上的，1881是运行在Docker容器里的，两者完全独立、互不影响
容器里的Node-RED能安装和原生一样的节点吗？可以，功能完全一致，只是运行环境不同
容器删了数据就没了，那生产环境怎么办？用 -v 参数做卷映射，把数据持久化到宿主机。见课后拓展第3点

课后拓展教学建议（供学有余力的学生） ​

课后拓展包含三个主题，不在课堂实践范围内，但教师应了解以应对学生提问：

  1. docker exec进入容器内部：调试时非常有用，可检查配置文件和日志
  2. Docker Compose多容器编排：用YAML文件描述多服务关系，一条命令统一启停。注意新版Docker使用 docker compose（空格）而非旧版 docker-compose（连字符）
  3. 数据持久化——卷映射：-v ~/nodered_data:/data 将宿主机目录挂载到容器内，生产环境必须使用

建议：在5.6实践课结束前用5分钟简要介绍这三个拓展方向，激发学生课后探索兴趣。特别是卷映射，可以强调"下节课如果用到Node-RED的数据，一定要用卷映射"。

五、思考与练习参考答案 ​

选择题 ​

  1. C（直接代替PLC执行控制逻辑不是平台的核心能力，平台提供的是连接、分析和应用托管）
  2. D（树根互联由三一重工孵化）
  3. B（海尔卡奥斯的核心模式是大规模定制）
  4. C（镜像是只读模板，容器是从镜像运行出来的实例）
  5. C（启动速度快、资源占用小是Docker相对虚拟机的优势）
  6. B（主机8080端口映射到容器80端口，格式为 -p 主机端口:容器端口）

判断题 ​

  1. √（平台向下连接设备，向上承载应用，类似工业界的应用商店）
  2. ×（阿里云IoT是互联网基因，树根互联是制造业基因，两者基因完全不同）
  3. √（挖掘机指数通过分析三一重工设备开工数据反映基建活跃度）
  4. √（Docker容器共享同一个Linux内核，因此比虚拟机更轻量）
  5. √（docker ps 查看当前正在运行的容器列表）
  6. √（Docker部署和原生安装的Node-RED功能完全相同，只是运行环境不同）
  7. ×（工业互联网平台可以部署在公有云上，也可以部署在企业私有服务器上）

思考题 ​

  1. 某工厂自己开发了一套设备监控系统，部署在自己机房的服务器上。算"用了工业互联网平台"吗？

    • 严格来说不算。这套系统是"自建"，不具备平台的核心特征——面向多行业多领域开放、支撑第三方应用开发与托管、提供设备接入SDK和数据分析工具等。它是一个"系统"，不是一个"平台"。但该系统可以接入工业互联网平台，成为平台生态的一部分。

  2. 中小型注塑机厂想要远程运维服务，只有3个软件工程师，应该怎么选？

    • 应选择"使用工业互联网平台"。理由：①只有3个工程师，自建全套不现实；②基于通用PaaS开发仍需大量底层工作（设备接入、协议适配、数据存储）；③工业互联网平台（如树根互联）已经提供了设备接入、数据分析和可视化看板等现成能力，3个工程师只需做业务定制即可。三一重工最初也是从自身需求出发孵化了树根互联，但那是三一这样的大型企业才有能力做的事。

  3. 用自己的话解释Docker"镜像"和"容器"的关系

    • 类比"应用安装包"和"已安装的应用"：镜像是只读的模板（安装包），容器是从镜像运行出来的实例（已安装并运行的应用）。一个镜像可以创建多个容器，就像一个安装包可以安装到多台电脑上。容器之间相互隔离，各自独立运行。

  4. 虚拟机和Docker容器的本质区别？为什么工业边缘网关更倾向于用容器？

    • 本质区别：虚拟机模拟完整硬件，每个VM运行独立的操作系统内核；Docker容器共享宿主机的Linux内核，通过命名空间和控制组实现进程级隔离。
    • 边缘网关倾向容器的原因：①资源占用小（MB级vs GB级），网关算力有限；②启动速度快（秒级vs分钟级），适合快速部署和故障恢复；③环境一致性，确保边缘和云端运行相同软件；④几十种工业软件共享内核比各自跑虚拟机高效得多。

七、学生常见错误预判与应对 ​

序号常见错误表现应对方案
1Docker权限问题permission denied while trying to connect to the Docker daemon socketsudo usermod -aG docker $USER 后必须退出SSH重新登录
2Docker下载太慢docker pull 长时间无响应提前配置国内镜像源（阿里云、清华源），或课前预下载镜像分发
