第1章 互联网基础（教师用书） ​

本章定位：全书的技术基石 课时安排：8课时（理论4 + 实践4） 学情分析：学生通常有上网经验，但对原理一无所知；对动手操作兴趣高，对纯理论有畏难情绪

一、本章教学目标 ​

知识目标 ​

  1. 了解互联网发展脉络（从ARPANET到5G，含中国部分）
  2. 理解TCP/IP四层模型与各层职责
  3. 掌握IP地址、子网掩码、网关、DNS基本概念
  4. 了解MAC地址、ARP协议、ICMP协议作用
  5. 了解互联网架构（接入网、城域网、骨干网）
  6. 了解常用应用服务与协议
  7. 了解网络安全基础（CIA、防火墙）

技能目标 ​

  1. 能在Windows/Ubuntu双环境下查看和配置IP
  2. 能使用ping/tracert诊断网络连通性
  3. 能使用nslookup查询DNS
  4. 能配置操作系统防火墙入站/出站规则

素养目标 ​

  • 分层思维：复杂系统通过分层分工实现高效运转
  • 排查思维：遇到问题不再只说"网坏了"，而是由近及远定位
  • 法治意识：网络空间不是法外之地，遵守网络安全法律法规
  • 岗位意识：从职业标准看待所学知识

二、课时分配与教学安排 ​

课次课时内容教学类型重点/难点
第1次课2h1.1 场景导入 + 互联网发展简史 + TCP/IP模型上半部分（网络接口层+网络层）理论重点：数据包封装过程
难点：ISP分层与网络架构
第2次课2hTCP/IP模型下半部分（传输层+应用层） + 1.3 IP地址/DNS/安全基础理论重点：TCP/UDP区别、公网vs私有IP
难点：NAT原理、DNS递归查询
第3次课2h1.2 实践：IP配置 + 连通诊断理实混合重点：双环境操作对比
难点：由近及远排查思路
第4次课2h1.4 实践：DNS查询 + 防火墙配置实践重点：防火墙规则逻辑
难点：入站/出站规则区别理解

三、各节教学实施建议 ​

1.1 从一封邮件到万物互联（2课时） ​

教学建议 ​

  1. 开场（10分钟）

    • 互动提问："你今天用了几次互联网？数据去哪儿了？"
    • 用快递单旅程动画演示，让学生直观理解
    • 工业预告要多花1分钟强调："这章知识就是工业互联网的基础，数据从设备到平台，走的也是这条路"

  2. 互联网发展简史（25分钟）

    • 重点讲"开放"带来的爆发，不要纠结年份细节
    • ARPANET"LO"的故事生动有趣，一定要讲，能活跃课堂
    • 中国部分要有自豪感，强调从接入者到引领者
    • 拓展知识（互联网管理机构）作为兴趣点，不做要求

  3. TCP/IP四层模型（50分钟）

    • 快递公司类比贯穿始终：
      • 寄件人=应用层
      • 打包员=传输层
      • 分拣员=网络层
      • 货车/飞机=网络接口层
    • 分层演示：4人小组，每人代表一层，传递纸条+加标签
    • OSI七层对照：提一句即可，不用展开
    • MAC地址/ARP协议：用"小区广播站"类比
    • 工业视角：识别设备接口是国标初级1.1的要求（为第3章打伏笔）

  4. 回顾反思（15分钟）

    • 小组讨论：如果不分层会怎样？
    • 请2-3组分享

教学辅助资源 ​

  • 配套视频：TCP/IP四层模型动画演示（可选）
  • 演示工具：Wireshark抓包展示（可选，第1次课可以不操作，只展示）

1.2 IP配置与连通诊断（2课时实践） ​

实践准备 ​

课前务必检查：

  1. 机房电脑能否安装VMware
  2. 网络是否允许虚拟机使用桥接模式（桥接模式是必须的，否则同学之间无法互相ping）
  3. 提前制作好Ubuntu虚拟机镜像克隆，避免课上花时间安装
  4. 准备网络故障模拟场景（比如拔网线、改网关）

教学流程 ​

  1. 虚拟机环境回顾（10分钟）

    • 检查学生是否已准备好环境
    • 快速演示如何切换网络模式

  2. 任务一：查看IP配置（25分钟）

    • 先Windows，后Ubuntu
    • 关键信息标注：IP/掩码/网关/DNS
    • 互动：看看谁的IP和网关在同一网段？
    • "小区大门"类比要反复强调

  3. 任务二：连通诊断（40分钟）

    • 由近及远是核心排查思路：
      • ping 127.0.0.1 （自检TCP/IP栈）
      • ping 网关（检查本地网络）
      • ping 百度（检查外网）
      • tracert 百度（看真实路径）
    • 岗位衔接：工业网络故障排查决策树要重点讲！
    • 可以故意制造几个小故障让学生练习排查
    • Windows和Ubuntu命令对比：tracert vs traceroute

  4. 任务三：修改IP（演示为主，15分钟）

    • 演示DHCP vs 静态IP的区别
    • 强调工业设备通常用静态IP
    • 安全提示：不要在机房乱改IP
    • Ubuntu的netplan配置只做演示，不要求学生掌握

  5. 成果展示+评价（10分钟）

    • 2-3组展示操作过程
    • 填写实践任务评价表

常见问题与解答 ​

学生问题回答要点
ping不通网关怎么办？先看网线插好没，再看IP和掩码是不是同网段
桥接模式无法获取IP？可能机房有IP限制，尝试NAT模式，牺牲互访功能
tracert中间有请求超时？正常，路由器可能禁ping，看最后到了没

1.3 网址背后的秘密（2课时） ​

教学建议 ​

  1. IP地址（20分钟）

    • 从"记住IP太难"引出域名的必要性
    • 公网vs私有IP：用"小区门牌号vs家里房间号"类比
    • NAT：用"小区快递柜"类比，这个学生更容易理解
    • 进阶内容：二进制运算只提一句，学有余力的同学看拓展阅读

  2. DNS（25分钟）

    • 电话簿类比：DNS就是查号台
    • 演示nslookup：查百度、查学校官网、换DNS服务器（8.8.8.8）
    • CDN：解释为什么不同地点ping百度IP不一样
    • DNS劫持：演示如果hosts文件被篡改会怎样（让学生警惕钓鱼网站）

  3. 应用服务与协议（20分钟）

    • 表格讲一遍，重点HTTP/HTTPS、DHCP
    • 客户端-服务器模型：用"餐厅吃饭"类比
    • DHCP非常重要，强调工业设备用静态IP，日常用DHCP

  4. 安全基础（25分钟）

    • CIA三元组：用例子讲（考试成绩=保密性，成绩不能改=完整性，查分系统不能挂=可用性）
    • 震网病毒一定要讲！震撼案例，让学生对工业安全有直观认识
    • 法治视角：《网络安全法》《数据安全法》结合着说
    • 防火墙：安检门类比，入站=查外来人员，出站=查出门人员

思政融入设计 ​

融入点结合内容教学方法
制造强国中国互联网从接入者到引领者，5G领跑数据展示+小组讨论
网络安全法治震网案例+网络安全法案例分析+情景讨论
工程师伦理DNS劫持、钓鱼网站的危害角色扮演（如果你是安全工程师）

1.4 DNS查询与防火墙配置（2课时实践） ​

教学流程 ​

  1. 任务一：DNS查询（30分钟）

    • 基本查询 + 换DNS服务器 + 反向查询 + 缓存操作
    • 演示清空缓存后访问变慢的现象
    • 讨论：如果DNS被劫持会怎样？

  2. 任务二：入站规则（30分钟）

    • 一步步演示创建过程
    • 验证环节：同学之间互相访问对方8080端口，看规则是否生效
    • 这步一定要做，学生能直观看到效果
    • 用"小区门禁"类比入站规则

  3. 任务三：出站规则（20分钟）

    • 阻止ping.exe，演示效果
    • 对比总结：入站=别人连我，出站=我连别人
    • 这个区别很多学生会搞混，多举生活例子

  4. 工业防火墙（10分钟）

    • 对比表格一定要讲
    • 强调"默认拒绝，白名单放行"是工业安全的核心
    • 这是国标初级1.4的要求

  5. Ubuntu ufw对照（可选，10分钟）

    • 时间充裕就演示，否则跳过

评价设计 ​

评价方式比重评价要点
实践操作40%完成所有任务，规则生效
小组互评30%协作能力，帮助同学
教师评价30%原理理解，安全意识

四、本章小结与拓展 ​

核心概念图谱 ​

建议在黑板或PPT上画一个清晰的逻辑链条：

用户输入网址 → DNS解析IP → TCP三次握手 → HTTP请求 → 路由转发 → 到达服务器 → 响应返回 → 页面显示

拓展活动建议 ​

  1. 网络故障排查大赛：设置3-5个故障场景，学生分组排查
  2. 校园网调研：看看学校网络架构，有几个网关，ISP是谁
  3. 家庭网络优化项目：给家里路由器设置更安全的防火墙规则

五、参考答案（思考与练习） ​

思考题（要点提示，鼓励学生有自己的思考） ​

  1. 分层的好处是解耦、复用、分工；不分层会像让快递员一人负责收件、分拣、运输、派送全流程
  2. 宿舍WiFi通常分配192.168开头的私有IP；验证方式：查IP+网关是否同一网段，或者查看路由器管理页面
  3. DNS劫持可能性：hosts文件被篡改、DNS服务器被攻击；排查：换8.8.8.8试试能否访问
  4. 公共WiFi风险：中间人攻击、窃听；防护：用VPN、访问HTTPS网站、不登录网银
  5. 流程：DNS解析 → TCP三次握手 → HTTP请求 → 数据封装传输 → 到达服务器 → 响应 → 页面渲染

选择题答案 ​

  1. B　2. B　3. C　4. C　5. B　6. C　7. B　8. B　9. B　10. B

判断题答案 ​

  1. ×（回环地址）　2. √　3. √　4. ×（UDP无连接）　5. ×（双向都重要）
  2. √　7. ×（IP→MAC）　8. √（端口不同）　9. √　10. ×（工业设备通常静态IP）
